# 네이티브 셸 검증 보강 (2차)

운영 앱(TWA, kr.jipgam.app)은 **교체하지 않는다.** 이 셸은 개발용 패키지(kr.jipgam.shell.dev)·디버그 서명이며 PR #295는 실험용으로 남긴다.

## 이번에 코드로 바꾼 것
1. **서울 누락 수정**: 지역 시트가 대전·세종·청주 3곳이었는데 웹 지역 메뉴는 서울 포함 4곳(운영 `/seoul/` 200 확인). `REGIONS`에 서울 추가.
2. **외부 주소 보안(`staysInApp`)**: https만 앱 안에서 열기. 허용 도메인은 `www.jipgam.kr`, `jipgam.kr`, 카카오(`kakao.com`, `kakaocdn.net`), `supabase.co`. 서브도메인은 `.kakao.com`처럼 점을 붙여 비교해 `evilkakao.com` 같은 비슷한 이름이 통과하지 않게 함(기존엔 `endsWith("kakao.com")`라 통과했음).
3. **밖으로 여는 주소 제한**: 외부 앱으로 넘기는 건 https·http·tel·mailto만. `intent:`·`file:` 등은 열지 않고 막음.
4. 점검: 파일 접근 허용·JS 브리지(`addJavascriptInterface`)·혼합 콘텐츠 허용 설정 없음, `usesCleartextTraffic=false`, `allowBackup=false`.

## 보안상 남은 검토(코드 미변경)
- 허용 도메인 `supabase.co` 전체는 넓다. 실제 쓰는 프로젝트 주소(`<id>.supabase.co`)로 좁히는 것이 안전. 프로젝트 주소는 운영 설정이라 확인 후 반영 필요.
- 카카오 로그인이 WebView 안에서 막히는 정책(구글 등 외부 로그인은 WebView 차단)이 카카오에도 적용되는지는 **실기기 확인 필요**.

## 저장소 차이와 기록 이전 대책
- TWA는 Chrome의 저장소를, 셸의 WebView는 앱 전용 저장소를 쓴다. **서로 안 보인다.** 비회원이 TWA에 담은 관심·방문 기록은 셸에서 안 보인다. 카카오 로그인한 계정 동기화분만 공유.
- 대책(권장 순서): ① 운영 앱 교체 전에 "내보내기/가져오기"(기록 파일 또는 코드) 기능을 웹에 추가하고 셸에서 가져오게 한다 ② 또는 카카오 로그인 후 동기화를 먼저 권장한다 ③ 교체하지 않고 병행 설치만. **이 기능은 아직 없으므로 기록 유실 위험이 있는 상태에서는 운영 앱을 교체하지 않는다.**

## 에뮬레이터에서 확인한 것 (실기기 아님)
Pixel 6형 Android 15 에뮬레이터: 설치, TWA와 병행 설치, 사이트 로딩, 네이티브 탭 5개 전환, 탭 이중 표시 없음, 시스템바 여백, 바텀시트 열림, 뒤로 가기 순서(탭→홈 탭→시트 닫기→종료). 스크린샷 `docs/`.

## NOT_TESTED (실기기 필요 또는 미실시)
- 햅틱, 키보드가 입력창을 가리는지, 카카오 로그인 복귀, 앱 재시작 후 탭·스크롤 상태, 기록 유지, 서울 지역 로딩(이번 추가분 전체 재시험 안 함), 공정한 시작 속도 비교(TWA 측정이 Chrome 첫 실행 화면에 방해받음), 외부 주소 차단 동작.
- 모두 **실기기 NOT_TESTED**로 둔다.

## 실기기 시험 방법 (따라 하기)
준비: 안드로이드 폰, USB 케이블, 컴퓨터(Windows).
1. 폰 설정 > 휴대전화 정보 > 소프트웨어 정보에서 **빌드 번호를 7번 연속 누르기** → 개발자 모드 켜짐.
2. 설정 > 개발자 옵션 > **USB 디버깅 켜기**. USB로 컴퓨터에 연결하고 폰에 뜨는 "이 컴퓨터를 허용"을 누르기.
3. 시험용 APK(`집감-네이티브셸-시험용.apk`)를 폰에 복사해 눌러 설치("출처를 알 수 없는 앱" 허용 필요할 수 있음). 운영 앱과 **따로** 설치되므로 기존 앱은 그대로.
4. 아래를 순서대로 해 보고 되면 O, 아니면 X와 어떻게 이상했는지 적기:
   - [ ] 앱 열기 → 하단 탭 5개, 위 상태바 색이 자연스러운가
   - [ ] 찾기 탭에서 검색창 누르기 → 키보드가 입력창을 가리지 않는가
   - [ ] 오른쪽 위 지역 바꾸기 → 대전/세종/청주/**서울** 모두 열리는가
   - [ ] 단지를 하나 열고 '관심' 누르기 → 앱을 완전히 닫았다 다시 열어도 남아 있는가
   - [ ] 뒤로 가기: 단지 → 목록 → 홈 탭 → 종료 순서가 자연스러운가
   - [ ] 카카오로 로그인 → 로그인 뒤 앱으로 잘 돌아오는가
   - [ ] 탭을 누를 때 진동이 느껴지는가(설정에서 터치 진동이 꺼져 있지 않을 때)
   - [ ] 일조 화면에서 동·층·시간을 바꿀 때 끊기지 않는가
5. 결과를 알려 주면 PR 문서에 "실기기 확인"으로 옮긴다. (컴퓨터에서 `adb logcat`으로 오류를 보는 일은 제가 대신한다.)

## 권고
**지금은 운영 앱을 네이티브 셸로 바꾸지 않는다.** 근거: ① 기록 이전 수단이 없어 비회원 기록이 사라질 수 있음 ② 실기기 검증이 하나도 없음 ③ 지금 불편의 큰 부분은 앱 껍데기가 아니라 웹 화면 구조(감사 결과)라 화면 개선이 먼저. 다음 순서: 웹 화면 구조 개선 → 기록 내보내기/가져오기 → 실기기 시험 → 그때 다시 비교.
