# UX 4-A: 홈·상세 재설계 기록

작성 기준 2026-11-06. 명령서 `JIPGAM_UX4A_Claude_Command.txt` 기준. 측정은 데모 빌드(가짜 데이터)에서 했고, 운영 데이터와 실제 사용자 시험은 하지 않았다.

## 1. 기존 문제 (변경 전, 390폭)
- 홈: 390폭에서는 입구가 이미 첫 화면에 있었음. 재방문 때 "이어서" 줄이 끼며 54px 밀림. 입구 3개가 같은 무게로 보여 으뜸 행동이 없음. 첫 방문은 인트로(지역 선택)를 거침.
- 상세: 첫 3,000px 안에 가격이 여러 번, 서로 다른 기준(실거래·추정·지표 비교·시세 구역)으로 나옴. 실거래는 그림 위 작은 칩, 추정은 약 1,000px 아래. 5개 범주 줄은 약 2,300px(1280폭 2,031px) 아래.

## 2. 홈 A/B
- A안(행동 중심): 입구 3개를 검색창 아래 큰 줄로, 카드덱은 그 아래. 장점: 모바일 첫 화면에 핵심 행동이 다 보임. 단점: 브랜드 인상이 약해질 수 있음.
- B안(카드 개성): 카드덱을 크게 먼저. 단점: 입구가 첫 화면에서 사라지고, 가장 큰 숫자가 지수라 추천처럼 읽힘. 옆으로 넘기는 동작은 어르신이 찾기 어려움.
- 선정: A안. 1280폭은 카드덱을 오른쪽에 그대로 둬 집감다움 유지.

## 3. 상세 A/B
- A안(가격 먼저): 맨 위 가격판에 실거래(굵은 상자)와 추정·비교용(점선 상자)을 나란히, 기준일·근거 건수·예산 차이를 바로 아래에. 5개 범주는 금박 카드 앞으로.
- B안(카드 안에서 정리): 금박 카드 안에서 정리. 단점: 카드가 길어져 범주가 여전히 아래, 어두운 바탕 작은 글자 증가.
- 선정: A안. 실거래와 추정 혼동, 범주 발견성이 실제 문제이고 카드는 거의 건드리지 않아 충돌이 적음.

## 4. 구현
- 상세: `.pb` 가격판 신설(h1은 가격판 머리로). 새 계산 없음. 실거래=최근 거래(lead), 추정=기존 price_ref. 카드 안 중복 가격 칸·가격 근거 칩 제거. 5개 범주 줄을 카드 앞으로, 휴대폰 2열.
- 홈: 입구 3개를 hero-copy 안 검색창 바로 아래로. 으뜸 행동 `.gate-main` 하나만 진한 남색(처음=찾기, 하던 프로젝트가 있으면 이어서 하기, app.js gates). 입구 CSS 5곳을 한곳으로 합침.
- 대비 보정: 신고가 배지(#d93f3e→#c0302f, 변경 전부터 있던 4.43:1), 가격판 괄호 글씨.

## 8. 검수 반영 (PR #275 수정 요청 6건)
1. **P0 취소 거래**: `djdex/site.py` `_lead_trade()`로 대표 거래 선정을 분리. 해제(취소)·(설정 시)직거래는 건너뛰고, 매매가 있으면 매매 우선(분양권·입주권은 매매가 없을 때만, 종류 표시). 유효 거래가 없으면 대표 가격을 비우고 이유("해제(취소)된 거래만 있어요" 등)를 표시. 변경 전에는 취소 거래만 있는 단지에서 취소된 9.80억이 "실거래"로 나왔음(`7-apt-cancel-only-390.png`). 원본 거래 데이터와 거래 목록은 수정하지 않음.
2. **면적 구분**: 실거래 칸에 실제 거래 면적, 추정 칸에 환산 기준 면적(전용 84㎡)을 각각 라벨로 표시. 면적이 다르면 "면적 기준이 달라요" 안내, 같으면 "두 가격 모두 ... 기준", 실거래가 없으면 "추정은 ... 실제 거래 가격이 아니에요". 추정 불가·거래 부족 단지도 화면 확인.
3. **임장 확인 요약**: 가격판 맨 아래에 "현장에서 확인할 점 N개 · 확인하고 기록하기"(기존 현장 모드 `data-field` 재사용, 확인 항목이 있는 단지에서만). 5개 범주는 위치 그대로. 상단 현장 체크 버튼보다 약하게(윤곽선 한 줄).
4. **모바일 홈**: 설명 문장 접기(검색창 문구가 대신 안내), 으뜸 행동을 한 줄(글 왼쪽·버튼 오른쪽)로, 보조 2개는 짧은 제목+작은 버튼 두 칸, 제목·검색 간격 압축. 390폭 입구 y447→337, 카드덱 y789(1차 수정본)·728(변경 전)→613. 재방문: 입구 501→388, 카드덱 782→665. 카드덱 윗부분이 첫 화면에 보임.
5. **전후 이미지**: `docs/ux4a/` 7장(홈 신규, 홈 재방문, 상세 390, 상세 1280, 거래 부족, 추정 없음, 취소만 있는 단지).
6. **검증**: node 86 / pytest 274 통과. 새 시험: 대표 거래 선정(없음·취소만·최신이 취소·직거래·분양권), 가격판 상태(취소 섞임·면적 다름·거래 적음). axe 홈·상세 3종 0건. 5폭×밝음/어둠×신규/재방문×홈/상세 40건 가로 넘침·오류·잘림·CLS 0.
   - Lighthouse 휴대폰(로컬 서버): 홈 성능 69→70, 접근성 100. 상세 성능은 측정마다 흔들림(변경 전 61·50·48, 후 58·59·60, 같은 컴퓨터 같은 조건 3회), 접근성 97→100.
   - 한계: 취소 거래만 있는 단지와 면적이 섞인 단지는 시험용 가짜 데이터로 확인. 운영 데이터·실제 사용자 시험은 하지 않음.
