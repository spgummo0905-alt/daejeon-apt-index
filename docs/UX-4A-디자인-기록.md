# UX 4-A: 홈·상세 재설계 기록

작성 기준 2026-11-06. 명령서 `JIPGAM_UX4A_Claude_Command.txt` 기준. 측정은 데모 빌드(가짜 데이터)에서 했고, 운영 데이터와 실제 사용자 시험은 하지 않았다.

## 1. 기존 문제 (변경 전, 390폭)
- 홈: 찾기·비교·임장 입구가 카드덱 위에 있지만 재방문 때 "이어서" 줄이 끼며 54px 밀림. 입구 3개가 같은 무게로 보여 으뜸 행동이 없음. 첫 방문은 인트로(지역 선택)를 거침.
- 상세: 첫 3,000px 안에 가격이 여러 번, 서로 다른 기준(실거래·추정·지표 비교·시세 구역)으로 나옴. 실거래는 그림 위 작은 칩, 추정은 약 1,000px 아래. 5개 범주 줄은 약 2,300px(1280폭 2,031px) 아래.

## 2. 홈 A/B
- A안(행동 중심): 입구 3개를 검색창 아래 큰 줄로, 카드덱은 그 아래. 장점: 모바일 첫 화면에 핵심 행동이 다 보임. 단점: 브랜드 인상이 약해질 수 있음.
- B안(카드 개성): 카드덱을 크게 먼저. 단점: 입구가 첫 화면에서 사라지고, 가장 큰 숫자가 지수라 추천처럼 읽힘. 옆으로 넘기는 동작은 어르신이 찾기 어려움.
- 선정: A안. 1280폭은 카드덱을 오른쪽에 그대로 둬 집감다움 유지.

## 3. 상세 A/B
- A안(가격 먼저): 맨 위 가격판에 실거래(굵은 상자)와 추정·비교용(점선 상자)을 나란히, 기준일·근거 건수·예산 차이를 바로 아래에. 5개 범주는 금박 카드 앞으로.
- B안(카드 안에서 정리): 금박 카드 안에서 정리. 단점: 카드가 길어져 범주가 여전히 아래, 어두운 바탕 작은 글자 증가.
- 선정: A안. 실거래와 추정 혼동, 범주 발견성이 실제 문제이고 카드는 거의 건드리지 않아 충돌이 적음.

## 4. 구현
- 상세: `.pb` 가격판 신설(h1은 가격판 머리로). 새 계산 없음. 실거래=최근 거래(lead), 추정=기존 price_ref. 카드 안 중복 가격 칸·가격 근거 칩 제거. 5개 범주 줄을 카드 앞으로, 휴대폰 2열.
- 홈: 입구 3개를 hero-copy 안 검색창 바로 아래로. 으뜸 행동 `.gate-main` 하나만 진한 남색(처음=찾기, 하던 프로젝트가 있으면 이어서 하기, app.js gates). 입구 CSS 5곳을 한곳으로 합침.
- 대비 보정: 신고가 배지(#d93f3e→#c0302f, 변경 전부터 있던 4.43:1), 가격판 괄호 글씨.

## 5. 측정 (데모, 전 → 후)
- 홈 신규 390: 입구 y 447(이전엔 카드덱 아래 입구, 별도 위치) → 447, 카드덱 y 728 → 789.
- 상세 390: 5개 범주 y 2300 → 672. 1280: 2031 → 475. 임장 확인 상자 y 1159 → 1747(밀림).
- 5개 폭(360/390/430/768/1280) × 밝음/어둠 × 신규/재방문 × 홈/상세 = 40건: 가로 넘침·오류·잘린 글자·CLS>0.02 모두 0.
- axe(WCAG 2.1 AA): 홈 0건, 상세 0건(변경 전 상세 1건 있던 것 포함 해결).
- Lighthouse 휴대폰: 홈 성능 69→69(변경 전도 같음), 상세 95→96, 접근성 홈 100·상세 97, 모범사례 96. SEO는 로컬 파일 측정이라 상세 66, 홈 69(운영 URL 아님).
- 테스트: node 86, pytest 272 통과. 새 시험 2개(가격판 구조, 홈 입구 순서).
- 작은 터치 대상(44px 미만)은 변경 전부터 있던 것들(헤더 지역·검색 버튼 등) 외에 이번에 새로 생긴 것 없음. 단, 상세 `A` 48×15 링크 등 기존 것은 그대로.

## 6. 남은 문제
- 임장 확인 상자가 약 590px 아래로 밀림.
- 홈 첫 방문 인트로 지연(약 4초 후 이동)은 이번에 바꾸지 않음.
- 홈 하단 정리(티커·띠 합치기), 카드 안 참고 지표 접기는 하지 않음.
- 360 / 430 / 768 폭 화면은 숫자로만 확인했고 눈으로 본 것은 390·1280.

## 7. 4-B 제안
- 조건 찾기 결과와 상세 연결(맞음·벗어남·자료 없음 표시, 근거 데이터가 있는 항목만).
- 이어서 카드에 진행률(조건 찾기 n/8, 임장 체크 진행).
- 방문 예정 날짜 선택(새 저장 구조 필요해 설계 후 통합).
- 상세 참고 지표·지수 계산 아코디언.
- 홈 하단 순서 정리, 인트로 건너뛰기 개선.
