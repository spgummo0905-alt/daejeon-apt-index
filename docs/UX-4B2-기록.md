# UX 4-B2: 진행 상황과 홈 경험

기준: 4-A 병합 커밋 `5c8e259`(최신 main, B1 미병합과 무관). 측정은 데모 빌드(가짜 데이터). 실제 사용자 시험은 하지 않았다.

## 이미 있던 것 (중복 제작하지 않음)
- 프로젝트 화면(`projects.js`): 후보·다녀온 단지·방문 기록 3칸 현황, 3단계 표시, "지금 할 일" 상자.
- 홈 "이어하기"(`app.js gates()/resume()`): 진행 중인 프로젝트 이름과 후보 수.
- 방문 기록(`visit-log.js`), 프로젝트 저장(`project-store.js`).

## 새로 한 것
1. **홈 이어하기 카드**: 프로젝트 이름 · 후보 N곳 · 다녀온 M곳 + "다음: …". 다녀온 수는 방문 기록(`DJVisitLog`)에서 이 프로젝트 후보 중 기록이 있는 단지 수로만 계산. 다음 행동은 그 숫자에서만 정함(후보 2곳 미만 → 후보 더 담기, 방문 0 → 비교하거나 순서 정하기, 일부 → 안 가 본 후보 K곳, 전부 → 기록 보며 다시 비교). 비교했는지는 기록이 없어 말하지 않음.
2. **프로젝트 단계 표시 바로잡음**: 변경 전에는 후보가 2곳 이상이면 "비교하고 순서 정하기"에 ✓가 붙었는데 비교한 기록은 어디에도 남지 않는다(전후 이미지 2번). 이제 ✓는 기록이 남은 것만(후보 담기, 다녀와서 기록하기). 비교·코스는 점선 "원할 때"로 두고, 방문을 먼저 해도 3단계가 바로 진행 중이 됨. "순서는 상관없어요" 안내 추가. 프로그레스 바는 쓰지 않음: 단계가 순서 있는 것처럼 보일 위험이 커서 체크리스트형을 유지.
3. **홈 하단 정리**: 구역을 전부 조사(아래 표). 삭제 없음. 검색·정렬이 되는 "전체 단지"를 지도 바로 뒤로(390폭 y8315 → y2890, 바로가기 줄 순서도 동일). 나머지(동네 온도·입주 물량·지역별 비교·입지 대비 가격)는 그 뒤로 밀리며 순서는 그대로. 카드덱·티커·카드첩·옥상은 건드리지 않음.
4. **인트로**: 이 기기에 관심 단지·프로젝트·방문 기록이 있는 사람은 건너뜀(빈 관심 목록은 기록으로 세지 않음). 처음 온 사람은 그대로 인트로부터. 지역 선택·"처음 볼 지역" 설정 이동 규칙은 그대로.

## 인트로 개선안 비교
- A안(채택): 기록 있는 사람은 건너뜀. 장점: 처음 온 사람의 소개 경험은 그대로, 다시 온 사람만 지연 제거. 단점: 기록을 지운 기기는 다시 인트로.
- B안: 인트로에 "건너뛰기" 추가. 장점: 누구나 즉시 이동. 단점: 기존 시험(`it-skip` 없음)과 소개 목적이 충돌, 첫 방문자의 지역 선택 흐름이 약해짐.
- C안: 최초 1회만 노출. 장점: 단순. 단점: 쿠키·저장 삭제 시 반복, 기록 유무와 무관해 남용 가능.
- 인트로 소요: 변경 전 새 창 진입 시 인트로로 이동(약 1.3초 로드)한 뒤 버튼을 눌러야 홈. 변경 후 기록 있는 사람은 홈 바로.

- 홈 이어하기 카드(390): 카드덱 y 약 690 유지(첫 화면에 윗부분 보임), 가로 넘침 0.
