# UX 4-C1b 기록: 운영에서 남아 있던 화면 흔들림

## 왜 다시 했나
4-C1(#279)은 데모 사이트에서 흔들림 0을 확인했지만, 운영 사이트에서 다시 재 보니 남아 있었음(대전, 같은 저장 상태, 5회씩).
- 홈 1280 재방문: 5회 중 2회 0.079 (나머지 0)
- 프로젝트 1280 밝게·다크: 5회 모두 약 0.045
- 홈 390: 0

## 원인 (운영과 같은 조건을 데모에서 재현해서 확인)
데모 서버는 스크립트(app.js)와 단지 자료(complexes.json)가 10~90ms에 도착해 흔들림이 안 보였음. 운영에서는 이들이 첫 그림 뒤에 도착하는 경우가 있음. 데모 서버에 900ms 지연을 걸자 운영과 같은 흔들림이 재현됨(홈 0.07, 프로젝트 모바일 0.045).
- 홈: 다시 온 사람은 '이어서 하기'가 으뜸 카드가 되며 입구 카드 높이가 줄었음(gates 441→368). 이 교체가 app.js 도착 뒤에 일어남.
- 프로젝트: 단지 자료가 오기 전 편집 영역이 숨겨져 있어 바닥글이 화면 안에 있다가, 자료 도착 후 아래로 밀려남(FOOTER 806→아래).

## 고친 것
- 홈(`templates/index.html`): 입구 카드 바로 뒤의 작은 코드가 저장된 기록(진행 중 프로젝트, 관심·최근 본 단지)만으로 정해지는 부분을 문서에서 바로 맞춤. 판단 기준은 `DJ.activeProject`와 같음(버전 1, 올바른 id·이름·지역, 보관 안 함, 후보 있음). 방문 수·다음 할 일 같은 세부 문구는 app.js가 그대로 채움. 못 읽으면 아무것도 하지 않음.
- 프로젝트(`projects.js`, `projects.html`, `style.css`): 저장된 프로젝트가 있으면 자료 대기 동안 `.pj-wait`로 편집 영역 자리를 미리 잡음(모바일 1000px, 901px 이상 720px). 자료가 오면 표시가 사라짐.

## 한계
- **운영에서는 아직 재지 않았음.** 병합·배포 후 같은 방법(운영 주소, 같은 저장 상태, 5회 이상)으로 확인해야 함.
- 지연 900ms는 운영 속도를 흉내 낸 값이지 운영 실측이 아님. 더 느린 연결에서는 다른 흔들림이 있을 수 있음.
- 홈 코드가 문서에 한 번 더 들어가 `app.js`의 판단과 같은 기준이 두 곳에 있음. 기준이 바뀌면 둘 다 고쳐야 함(시험이 일부를 지킴).
- 첫 4-C1에서 '목표 달성'이라고 쓴 것은 데모 기준이었고 운영에서는 일부만 맞았음을 정정함.
