측정: 같은 25개 구 목록, 같은 스타일(운영 style.css), 같은 브라우저, 360/390/430/1280 폭. 이미지: `docs/ux4c2/seoul-filter-4options.png` (390px).

| 안 | 모양 | 필터 높이(390) | 목록 시작 위치(390) | 한 번에 보이는 구 | 구 하나 고르는 탭 수 |
|---|---|---|---|---|---|
| A 지금 | 선택 상자 1개 | 48px | 198px | 상자를 열면 전체 | 2탭(열기 → 선택) |
| B 칩 전부 펼침 | 4열 격자 25칩 | 503px (360폭 580px) | 653px | 25개 모두 | 1탭, 대신 화면 3분의 2 차지 |
| C 한 줄 넘기기 | 가로로 넘기는 칩 한 줄 | 44px | 194px | 3~4개 (나머지는 옆으로 넘겨야 보임) | 보이는 구 1탭, 나머지는 넘기고 1탭 |
| D 자주 찾는 5 + 다른 구 상자 | 칩 5개 + 선택 상자 | 152px | 302px | 5개 + 상자 | 5개는 1탭, 나머지 2탭 |

- 1280에서 B는 칩 높이가 40px이라 터치 기준(44px)에 못 미침(26개 모두). 나머지 안은 44~48px.
- 가로 넘침은 모든 안에서 없음.
- 눈으로 본 결과: B는 한 화면의 대부분을 필터가 차지해 아래 목록이 밀려 보이지 않음. C는 4번째 칩이 잘려 넘기는 걸 짐작할 수 있지만 25개를 찾으려면 8번 이상 넘겨야 함. D는 깔끔하나 '자주 찾는 5곳'을 정할 근거(실제 클릭 자료)가 없음.
- **선택: A 유지.** 이유: 목록이 가장 위(198px)에서 시작하고 25개 구를 다 찾을 수 있고 2탭이면 충분. B·C는 화면을 차지하거나 찾기 어렵고, D는 근거 없이 구를 골라야 함.
- 한계: 실제 사용자 클릭·시간은 측정하지 않았음(자동 측정만). D는 사용 통계가 쌓이면 다시 검토할 만함.


## 5. 데이터 상태별 표시 점검 (운영 사이트, 2026-11-07)

- 추정 가격 없음("최근 거래가 적어 계산하지 않았어요"): 대전 115, 세종 33, 청주 68.

## 6. 임장 여정 연결 (데모 사이트, 390px, 같은 저장 상태)
| 연결 | 결과 |
|---|---|
| 홈 '이어서 하기' → 프로젝트 | 누르면 프로젝트 화면이 열리고 그 프로젝트(후보 3곳)가 선택돼 있음 ✔ |
| 상세 '현장에서 확인할 점' → 현장 모드 | 누르면 현장 시트가 열리고 항목 13개가 나옴 ✔ |
| 예정일이 있는 프로젝트 → 방문 기록 | 예정일 상자 근처가 아니라 아래 후보 카드에 '방문 기록 남기기' 버튼이 있음. 예정일 상자 안에는 '방문 기록' 버튼이 없음(바꾸기·취소만) → **예정일 당일에 바로 기록으로 이어지는 길은 없음(미구현, 아래 제안)** |
| 예정일 취소 시 보존 | 취소 후 후보 3, 이름·목표, 방문 기록 메모, 관심 2곳 모두 그대로 ✔ (예정일만 비워짐) |
| 새로고침·다른 화면 갔다 뒤로 | 취소·재설정한 예정일과 나머지 데이터가 그대로 복귀 ✔, 스크립트 오류 0 |

제안(미구현): 예정일이 오늘이거나 지났을 때 예정일 상자 상태 문구 옆에 '방문 기록 남기기' 버튼을 한 개 더하는 방안. 명령서가 '홈·코스에 날짜를 무리하게 중복 노출하지 말 것'이라 해서 **프로젝트 화면 안에서만** 연결하는 최소안. 이 변경은 실제 이득이 있는지 사용자 확인 후에 하는 것이 좋음(현재 후보 카드에 이미 같은 버튼이 있어 중복일 수 있음).


## 4. 화면 실물 점검 (데모 사이트, 390px, 같은 저장 상태: 후보 3, 관심 3)
점검한 화면: 조건으로 찾기, 비교, 임장 코스, 관심(내 기록), 단지 상세, 프로젝트. 이미지: `docs/ux4c2/screens-*.png`. 6개 화면 모두 가로 넘침 없음, h1 하나, 스크립트 오류 없음.
눈으로 본 결과(문제로 보이는 것만):
- 찾기: 다음 행동(다음 버튼)이 하단에 분명함. 문제 없음.
- 비교: '임장 배지를 받았어요' 알림이 화면 위를 가림(일시적 알림, 데모 상태에서만 뜸). 주 행동 '이 단지들로 임장 코스 만들기'가 첫 화면 아래에 있어 스크롤이 필요함 → **제안(미구현)**: 비교 단지를 담은 직후 그 버튼을 위로 올릴지 사용자 확인 필요.
- 임장 코스: 카드 가로 넘김과 코스 상자가 위아래로 이어져 정보가 많음. 주 행동은 분명함.
- 관심: 헤드 문구가 길어(2줄 설명 + 저장 안내 2줄) 첫 화면의 절반을 쓰고 핵심 카드 '관심 단지'가 하단 탭 근처에서 시작함 → **제안(미구현)**: 저장 안내 문구 접기.
- 상세: 가격판, 면적 안내, 현장 확인 줄이 한 화면에 들어옴. 문제 없음.
- 프로젝트: 정돈됨.
- 데모 노란 띠('데모 화면입니다')는 데모에만 있고 운영에는 없음(비교 시 감안).

### 터치 영역(44px 기준) — 실제로 고친 것
측정 전 → 후 (390px, 눌러지는 요소 중 40px 미만):
- 코스에서 빼기(×) 30px → 44px (임장 코스 단지마다)
- 코스 체크 목록 한 줄 39px → 44px 이상
- '이 단지까지 길찾기' 38px → 44px
- 단지 목록 위치 링크(상세 상단) 글자 15px → 누르는 범위 44px(글자 크기는 그대로)
- 코스 단지 이름 링크 29px → 누르는 범위 44px
- 새로 안 고친 것(남은 것): 본문 안의 짧은 글 링크(예: '산출 방법', '거래 내역', 비교의 단지 이름 링크 15px) — 글 속 링크는 높이를 키우면 줄 간격이 깨져 보류. 체크 상자 자체(17px·24px)는 감싼 줄(label)이 44px라 줄을 누르면 동작함(상자만 누르는 정밀 측정은 안 함).
- 시험 1건 추가(CSS 값 고정). 

## 하지 않은 것 / 한계

## 7. 관심 화면 안내 접기 (사용자 '추천대로' 승인 후 실제 변경)
- 변경: 관심 화면(`my.html`) 위쪽 설명 2줄 + 저장 안내 2줄을 프로젝트 화면과 같은 한 줄 접기(`hero-note`)로 묶음. 펼치면 같은 문구가 그대로 나옴(지운 문구 없음). 저장 안내 칸은 접힌 안에 두어 로그인하면 문구가 바뀌는 기능 유지.
- 측정(390px, 데모): '관심 단지' 시작 위치 y646 → y553(93px 위). 1280은 y555 → y517. 가로 넘침 0, 오류 0. 이미지: `docs/ux4c2/my-fold-390.png`.
- 눈으로 확인: 접힌 줄이 깔끔하고 아래 카드와 간격 정상. 펼침 동작 확인.
- **하지 않은 것**: '예정일 상자에 방문 기록 남기기 버튼 추가'는 후보 카드에 같은 버튼이 이미 있어 중복 우려로 보류(사용자가 '추천대로'라 해서 제 추천인 '안 함'을 따름). 서울 구 필터는 선택 상자 유지.
