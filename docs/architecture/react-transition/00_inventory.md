## 2. React를 붙이기 쉬운 곳 / 어려운 곳
- 쉬운 곳: 입력·상태가 많고 작은 독립 영역. 예) 가격 빠른 버튼(pay.js 56줄), 미니 카드, 등급 배지, 빈 상태 안내.
- 어려운 곳: `DJ` 전역을 많이 쓰는 화면. app.js(273회), prefs.js 60, field.js 60, sync.js 55, my.js 47, course.js 39. 이 화면들은 저장·계정 동기화와 얽혀 있어 한꺼번에 옮기면 이중 저장·중복 클릭 위험이 큼.
- 화면 DOM을 직접 만드는 코드(`el(...)` 47곳)와 DOM 구조·문구를 고정한 시험(Python 시험 파일 45개 중 다수, test_demo_build.py만 65곳)이 많아, 옮기면 시험을 다시 써야 함.

## 3. 위험 (문서와 일치)
- 높음: 중복 DOM 이벤트(React와 기존 JS가 같은 요소를 소유), 사용자 데이터 손실(키·동기화 규칙), SEO·서비스워커 회귀.

- 열린 PR #392(SEO URL 정리)와 같은 영역을 건드리지 않아야 함. #325(WebGL), #295(Android 셸)는 병합 대상 아님.

1. 전체 SPA 교체는 하지 않음. 근거 부족, 위험 높음(문서 결론과 같음).
2. 한다면 R1(격리 폴더 `frontend/react-pilot/`)부터: 운영 영향 0, 읽기 전용 미니 카드·등급 배지·빈 상태 3개만.
