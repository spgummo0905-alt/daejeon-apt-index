## 바뀐 것
- **찾기 결과**: 예전 큰 게임 카드(지표 막대 4줄) 대신 **미니 카드**(건물 그림 · 지역·연식 · 단지명+등급 · 84㎡ 추정가) 한 장씩. 조건에 맞는 이유(예: "30평 6.1억 외 1개 평형")는 카드 위 한 줄 칩. 카드 전체가 단지 상세 링크, 오른쪽 아래 **별(44×44)**이 기존 관심 저장(`DJ.toggleFav`)을 그대로 호출. 휴대폰 1열, 넓은 화면 여러 열.
- **지도 핀 → 하단 시트**: 이름·가격·등급을 나눠 적던 칸을 같은 **미니 카드 한 장**으로(지수 포함). 단지 상세 / 일조 보기 / 후보에 담기 버튼과 "추정 시세예요" 안내는 그대로.
- **홈 지도 요약**(카카오 지도)도 같은 미니 카드로. 좌표·핀·클러스터·가격대 필터·점 지도 대체 화면은 건드리지 않았습니다. 위치 미확인 단지 목록 대안도 그대로.
- 프로젝트 화면 안에서 쓰는 "프로젝트 후보로 담기" 버튼은 새 카드에도 붙도록 연결(`.hc-fcard`).

## 변경하지 않은 것
결과 수·정렬·가격/평형 필터 계산(`pass`·`fit`·`works`), 조건 단계·요약 줄, 관심 저장 키, 지도 데이터·좌표, URL, 일조·카드첩 화면.

## 검증
- 노드 106 / 파이썬 301 통과. 시험 1개는 옛 함수 이름(`DJ.card(...)`)을 문자열로 찾던 것이라 새 호출(`DJ.hc.fcard`)과 관심 저장 호출을 확인하도록 고쳤습니다(검증 대상은 줄이지 않음).
- 찾기(390/360/430/다크): 결과 24곳 카드 표시, 별 44×44가 카드 안, 가로 넘침 0, JS 오류 0, 별 누르면 관심 저장 0→1, 카드 링크 `apt/DEMO-0047.html`.
- 지도(390/360/430/다크, 점 지도): 핀 탭 → 시트 열림 + 카드 + 가격, 시트가 하단 탭 위, 글자 잘림 0, 후보에 담기 저장 확인, 오류 0.
- 접근성(axe) 지도 화면 위반 0. 찾기 화면은 **5건(0곳 선택지의 흐린 글자 대비)**이 나오지만 #328(변경 전)에서도 똑같이 나오는 기존 문제이고 새 카드와 무관합니다(별도 수정 필요).

## 목표 시안과 다른 점
- 시안은 찾기 첫머리에 "전체 보기 / 6억 이하 / 지수 78점 이상" 빠른 필터와 "3개 단지" 카드 3장을 바로 보여 주지만, 구현은 기존 8단계 질문 흐름 위에 카드 결과를 얹었습니다(필터 계산 변경 금지 조건).
- 시안 지도는 큰 지도 위에 가격 핀과 하단 카드가 떠 있고 "카드 보기 →" 버튼이 있지만, 구현은 기존 핀·시트 구조를 유지하고 시트 안 카드만 교체했습니다. 데모 사이트는 카카오 지도가 아닌 점 지도로만 확인했습니다.
- 건물 그림은 평면 추상 그래픽(실제 외관 아님).
