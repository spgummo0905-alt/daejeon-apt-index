비교: `img/c4-compare.png`(목표 MY / 구현 MY / 목표 카드첩 / 구현 카드첩, 390), `img/c4-sizes.png`(360·430·다크·첫 방문), 흐름 영상 `img/c4-flow.mp4`(MY → 카드 옆으로 넘김 → 관심 목록 → 카드첩 열기).

## 바뀐 것
- **MY 맨 위 "내 카드첩"**: 모은 카드 수·임장 배지 수(기존 앨범·배지 저장에서 세기만 함) + **수집 카드 2~3장**(관심 단지 → 없으면 최근 본 단지). 등급별 틀(S·A 금, B 파랑, 그 외 은색), 다녀온 단지는 "다녀옴 11.08" 도장. 기록이 없는 첫 방문자는 안내 + "조건으로 찾아보기" 빈 상태. 카드첩 입구가 첫 화면에 보입니다.
- **관심 단지 목록**: 큰 게임 카드 대신 **미니 카드**(+ 도장). 비교·임장 버튼·숫자 세 칸·세 칸 탭·"다음 행동" 줄은 그대로.
- **수집 카드(JS)** `DJ.hc.collect`를 공통 카드에 추가(서버 틀 `_card.html`과 같은 모양).
- **가격 표기 정합**: 서버가 그리는 카드 가격이 `3.42억`(두 자리) 형식이어서 `complexes.json`·카드 이미지·휴대폰 카드(`6.8억`, 한 자리)와 달랐던 것을 한 자리로 통일했습니다. 숫자 값은 같고 표기 자리수만 같아졌습니다. 상세 화면 실거래·추정 칸의 두 자리 표기(`6.81억`)는 그대로(근거 표기).

## 변경하지 않은 것
저장 키(`favs`·`recent`·`album`·`visit:`·배지)·URL·카드첩 수집/배지 로직·공유 PNG 생성기(`cardgen.js` 750×1050, **이번 PR에서 수정 없음**)·상세 가격 칸.

## 정합성 검사 (같은 단지 5곳 × 화면 5개, 데모 자료)
상세(등급·지수·가격 data)·상세 카드·비교 카드·찾기 카드·공유 이미지 입력값을 `complexes.json`과 대조: **불일치 0**. 카드첩 앨범 카드 4장도 등급·이름·지수·가격·도장 **불일치 0**(도장은 방문 기록이 있는 단지만).

## 검증
- 노드 106 / 파이썬 301 통과(시험 수정 없음).
- MY 390(기록 있음/첫 방문)·360·430·다크: 가로 넘침 0, JS 오류 0, 수집 카드·미니 카드 값 일치, 빈 상태 표시.
- 접근성(axe) MY·카드첩 × 390/768/1280 × 라이트/다크 **30건 통과**.
- 캡처에서 찾아 고친 것: 수집 카드 위 `JIPGAM · S TIER` 글자가 360에서 줄바꿈되던 것(한 줄·말줄임), 도장이 등급 칩을 가리던 것(왼쪽으로 이동).

## 목표 시안과 다른 점 (정직하게)
- **카드첩 화면의 카드 면은 아직 예전 모양**입니다(`DJ.miniCard`). 시안은 수집 카드 2열 "아파트 컬렉션"과 "모은 카드가 나의 기준이 됩니다" 파란 머리 카드지만, 이번에는 MY 쪽만 새 수집 카드로 바꿨습니다. 앨범 카드는 뒤집으면 임장 메모가 나오는 기존 동작·시험이 걸려 있어 데이터만 대조(불일치 0)하고 모양 교체는 보류했습니다. → **C4 후속 또는 C5에서 결정 필요.**
- 시안 MY의 "이어할 일" 1개 큰 카드와 상단 파란 인사 카드(MY JIPGAM)는 없습니다(기존 "다음 행동" 줄 유지).
- 시안 MY는 숫자 칸이 "관심 카드/임장 프로젝트/방문 기록" 이름이지만 구현은 기존 이름 유지.
- 건물 그림은 평면 추상 그래픽(실제 외관 아님).
