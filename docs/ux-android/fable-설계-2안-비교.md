# 집감 일조 '한 화면 작업 무대' 설계 + 핵심 여정 + TWA

전제(두 안 공통)
- 390×844, 상태바 24 + 하단 탭 56 제외 → 쓸 수 있는 세로 764px.
- 목표: 결과 숫자 앞 누를 곳 22개 → 8개 이하. 결과 숫자는 y<120에 고정.
- 계산은 shadow.js 그대로. 드래그 중에는 "현재 시각 1칸"만 즉시 그리고, 하루 합계(약 N시간)는 손을 뗀 뒤 120ms 안에 갱신. 갱신 중엔 숫자를 흐리게만 하고 자리는 유지.
- 한계 한 줄은 항상 같은 문장: "추정한 참고용 · 실내 채광·법적 일조권 아님".

## 요청 1. 일조 한 화면 작업 무대 2안

### 1안 「레일」 — 층 레일을 건물 옆에 세운다

```
y=0   ┌──────────────────────────────────────┐ 44  상단: ◀  트리풀시티5 ▾        ⓘ
y=44  │ 약 5시간            11:00~16:00 가림 │ 64  결과 띠(고정, 숫자 36px)
      │                        102동이 가장 큼│
y=108 │ [  동지  |  하지  |  오늘  ]         │ 44  날짜 세그먼트
y=152 │ 층 ┃  ┌────────────────┐ [입체|평면|층별]│
      │ + ┃  │                │             │
      │ ┃ ┃  │   2.5D 무대    │             │ 420 무대
      │ ● ┃  │  (334×420)     │             │     좌 56px 층 레일
      │8층┃  │                │     [전체]  │
      │ − ┃  └────────────────┘             │
y=572 │ − ──────●──────────── +   12:00 가림 │ 72  시간 슬라이더(트랙에 가림 막대)
y=644 │ 추정한 참고용 · 실내 채광·법적 일조권 아님│ 24  한계
y=668 │ [   이 조건으로 방문 계획에 저장   ]   │ 52  행동
y=720 │        현장 확인 · 근거 ▾             │ 44  접힘 힌트(스크롤 시작)
y=764 └──────────────────────────────────────┘ 56  하단 탭
```

1. 세로 예산: 44 / 64 / 44 / 420 / 72 / 24 / 52 / 44 = 764. 무대가 55%.
2. 결과 띠(y44–108): 왼쪽 "약 5시간" 36px 굵게, 오른쪽 두 줄 14px(시간대, 가장 크게 가리는 동). 동·층·날짜·시각 어느 것을 바꿔도 이 자리만 바뀐다. 시각 슬라이더를 움직이면 오른쪽 둘째 줄이 "12:00 · 102동에 가려요 / 안 가려요"로 바뀌고 하루 합계는 그대로.
3. 날짜 세그먼트(y108–152): 3칸 균등, 높이 44. 선택 즉시 재계산.
4. 무대(y152–572): 
   - 좌측 56px 층 레일: 트랙 8px, 손잡이 44×44 원 안에 "8층" 글자, 위 [+] 아래 [−] 각 44×44, 5층마다 눈금. 레일 길이 = 무대 높이 − 버튼 2개 = 332px. 트랙 탭 = 그 층으로 점프, 드래그 = 연속, ± 길게 누르면 반복. 손잡이 글자 탭 → 층 격자 시트(아래 "시트").
   - 레일의 y와 건물 노란 띠의 y가 같은 방향(위=높은 층). 손잡이를 올리면 노란 띠가 올라가고 창→해 광선이 앞 동 위로 넘어가며 빨간 ✕가 사라진다. 이것이 "왜 앞 동이 가리는지"를 글 없이 설명하는 장치다.
   - 우측 334px SVG. 우상단 보기 세그먼트(입체/평면/층별, 3×44, 반투명 흰 바탕). 우하단 [전체] 칩(집중 중에만 보임).
   - 동 바뀌면 최고층 갱신. 현재 층이 더 높으면 최고층으로 내리고 토스트 "102동은 25층까지 있어요".
5. 동 터치 → 카메라 집중: viewBox만 바꾼다. 목표 상자 = (선택 동 ∪ 지금 시각에 가리는 동 ∪ 광선) + 15% 여백, 확대 상한 2.2배, 240ms ease-out, requestAnimationFrame으로 viewBox 4값 보간. 회전·기울기 고정. 빈 땅 탭 또는 [전체] → 원래 viewBox. 동 길게 누르면 작은 칩(102동 · 25층)만, 선택은 짧은 탭으로.
6. 시간 슬라이더(y572–644): −/트랙/+ 한 줄, 손잡이 44, 05:00–20:00 60칸 스냅. 트랙 바탕에 하루 가림 막대를 그대로 깔아 "주황 구간에 손잡이가 들어가면 가려짐"이 보이게. 12:00에 눈금. 라벨 "12:00 · 가려짐"은 손잡이 위에 따라다님. 무대의 해·줄무늬 그림자·광선이 같이 움직인다.
7. 결과 숫자 위치: y44–108, 화면 어디서도 스크롤 전에는 안 밀린다. 아래로 스크롤하면 결과 띠만 sticky(44px 한 줄로 축소: "약 5시간 · 11~16시").
8. 시트가 열리는 때: 단지 이름 탭(단지 고르기, 검색 포함) / 레일 "8층" 글자 탭(층 격자: 6열 44px, 높은 층이 위, 현재 층 강조, 고르면 즉시 닫힘) / ⓘ 탭(한계·근거·현장 확인) / 저장 버튼(예정일·메모, 기존 임장 저장 구조 그대로) / 접근성 "목록" 칩(동 목록). 모든 시트는 history state를 넣어 Android 뒤로가기로 닫힌다.
9. 빈 상태·오류·자료 없음:
   - 단지 미선택: 무대에 회색 실루엣 + 가운데 큰 버튼 "단지 고르기". 결과 띠는 "—".
   - 동 배치 자료 없음: 무대 대신 "이 단지는 모형 자료가 없어요" + 층별 표만 제공(입체/평면 비활성). 숫자 지어내지 않음.
   - 동이 1개뿐: 모형은 보이고 결과 띠 "단지 안에서 가리는 동이 없어요 · 단지 밖 건물은 계산에 없어요".
   - 계산 실패: 결과 띠 "계산을 못 했어요 [다시 시도]", 무대는 마지막 그림 유지.
   - 계산 중: 숫자 자리 흐림, 무대는 즉시 반응(1칸 계산은 동기).
10. 접근성 대체: 레일·시간 슬라이더는 role=slider, aria-valuetext "8층"/"12시 00분, 가려짐", 방향키 1칸, PageUp/Down 5칸. 동 선택은 SVG 버튼과 별도로 "동 목록" 시트(실제 listbox)가 같은 상태를 바꾼다. 무대 아래 aria-live(polite) 한 줄: "12시, 102동에 가려요". 층별 보기는 실제 표(th/td)라 스크린리더·목록 조작의 기본 경로.
11. 640 높이 적응: 상단 40 / 결과 52(한 줄 "약 5시간 · 11~16시 · 102동") / 날짜 40 / 무대 300(레일 동일) / 시간 56 / 한계 20(결과 띠 아래 작은 글로 이동 가능) / 행동 44 → 552 + 탭 56 + 상태바 24 = 632. 접힘 힌트는 제거하고 스크롤 자체가 힌트. 우선순위: 숫자 > 무대 > 층 > 시간 > 날짜 > 보기 > 한계.

### 2안 「데크」 — 무대를 전폭으로, 조작은 아래 데크에

```
y=0   ┌──────────────────────────────────────┐ 44  상단: ◀ 트리풀시티5 ▾ [입체|평면|층별]
y=44  │ ┌약 5시간 · 11~16시┐                  │
      │ └─────────────────┘                  │
      │                                      │ 476 무대(390 전폭)
      │            2.5D 무대                  │     결과 칩 좌상단 겹침
      │                                      │     [전체] 우하단
      │        [ 동지 | 하지 | 오늘 ]          │     날짜 세그먼트 하단 겹침
y=520 │  [ − ]        8층        [ + ]        │ 64  층 스텝퍼(숫자 탭→격자 시트)
y=584 │ − ──────●──────────── +   12:00 가림 │ 72  시간
y=656 │ 추정한 참고용 · 실내 채광·법적 일조권 아님│ 24  한계
y=680 │ [   이 조건으로 방문 계획에 저장   ]   │ 52  행동
y=732 │                                      │ 32  여유
y=764 └──────────────────────────────────────┘ 56  하단 탭
```

1. 세로 예산: 44 / 476 / 64 / 72 / 24 / 52 / 32 = 764. 무대가 62%, 폭 390.
2. 결과 칩: 무대 좌상단 겹침, 반투명 흰 바탕 160×56, "약 5시간" 28px + "11~16시" 13px. 가장 크게 가리는 동 이름은 칩 아래 한 줄로 길어진다. 칩 탭 → 근거 시트.
3. 층 스텝퍼: [−] 64×56, 가운데 "8층" 28px(탭하면 층 격자 시트), [+] 64×56. 길게 누르면 반복. 격자 시트는 1안과 동일.
4. 동 터치·카메라: 1안과 같음(viewBox 보간). 전폭이라 13동 단지도 집중 전에 식별 가능.
5. 시간 슬라이더: 1안과 같음, 위치만 y584.
6. 시트 열림, 빈 상태, 접근성: 1안과 동일. 단 날짜 세그먼트가 무대 위에 겹치므로 무대 하단 48px는 터치 대상 없는 여백(동이 거기 그려지면 viewBox 아래 여백 12% 확보).
7. 640 적응: 무대 320(칩·날짜 겹침 유지) / 스텝퍼 56 / 시간 56 / 한계 20 / 행동 44 / 상단 40 = 536 + 80 = 616.

### 장단점과 추천

| | 1안 레일 | 2안 데크 |
|---|---|---|
| "왜 가리나" 글 없이 이해 | 레일 위↑ = 노란 띠↑ = 광선이 앞 동을 넘김. 손 움직임과 그림이 같은 방향·같은 높이라 인과가 몸으로 보인다 | 층 숫자가 건물과 떨어져 있어 "숫자 바뀜 → 그림 바뀜"을 눈이 따로 찾아야 함 |
| 무대 크기 | 334폭, 13동 단지는 집중 전 작음 | 390폭, 넓음 |
| 어르신 조작 | 세로 레일 드래그가 낯설 수 있음(± 버튼이 보완) | ± 스텝퍼가 가장 익숙 |
| 슬라이더 2개 혼동 | 세로/가로로 방향이 달라 구분됨 | 해당 없음 |
| 겹침 가독성 | 없음 | 칩·세그먼트가 그림 위에 겹쳐 건물과 충돌 가능 |
| 결과 숫자 안정성 | 고정 띠, 항상 같은 자리 | 칩이 그림과 겹쳐 눈에 덜 띔 |

추천: 1안 레일. 이유 하나로 요약하면 "층을 올리는 손동작이 그림 속 창을 올리는 동작과 일치"해서 설명 문장이 필요 없다. 보완으로 2안의 층 격자 시트와 ± 반복을 레일에 그대로 붙인다(레일 드래그가 안 되는 사람은 ±와 격자로 같은 일을 할 수 있다).

### 사용자 과업 시험 계획(5명, 설명 없음)

- 대상: 60세 이상 2명, 30~50대 2명, 20대 1명. 본인 휴대폰 또는 390급 Android. 트리풀시티5(13동)로 시작.
- 지시문 한 문장만: "이 아파트에서 관심 있는 동을 하나 골라, 원하는 층으로 바꾸고, 낮 12시에 해가 가려지는지 확인한 뒤 방문 계획으로 저장해 보세요."
- 관찰 항목(각각 시간·도움 요청·오조작 횟수 기록):
  1. 첫 동 탭까지 걸린 시간. 동 대신 결과 숫자·범례를 먼저 누르는지.
  2. 층 변경에 쓴 수단(레일 드래그 / ± / 격자 시트). 노란 창 띠를 직접 누르려는 시도 횟수(예상 오조작, 3회 이상이면 띠에도 탭→격자 연결).
  3. 정오 확인: 시간 손잡이를 12시로 가져갔는지, 또는 결과 띠 시간대만 읽고 답했는지. 답이 맞는지(실제 상태와 대조).
  4. "아, 앞 동 때문이구나" 류의 발화가 어느 시점에 나오는지(광선·✕를 본 뒤인지). 핵심 지표.
  5. 저장 버튼을 찾는 시간, 시트에서 예정일 입력 완료.
  6. 종료 질문 2개: "이 숫자가 확실한 건가요?"(기대 답: 참고용/추정), "층을 올리면 왜 가림이 줄었나요?"(기대 답: 앞 동보다 높아져서).
- 성공 기준: 5명 중 4명이 도움 없이 4단계 완주, 1인당 90초 이내, 정오 판단 정답률 5/5, 종료 질문 1에 "확실하다"고 답한 사람 0명, 질문 2를 자기 말로 설명한 사람 4명 이상. 미달 항목이 있으면 그 항목만 수정하고 2명으로 재시험.

### 데스크톱 1280 · 태블릿 768 방침

- 1280: 2열. 왼쪽 400px 조작 열(단지, 날짜, 결과 띠, 층 레일을 가로 슬라이더로 펼침, 시간, 한계, 저장), 오른쪽 880px 무대 + 보기 세그먼트. 숫자는 왼쪽 열 맨 위 고정. 날짜 비교·근거는 왼쪽 열 아래 펼침.
- 768 가로: 1280과 같은 2열(조작 300 / 무대 468). 768 세로: 모바일 1안 그대로에 무대만 560px로 키움. 레일 폭은 그대로 56.

## 요청 2. 이번 밤에 완결할 핵심 여정

| 후보 | 효과 | 위험 | 난이도 | 비고 |
|---|---|---|---|---|
| 홈 | 높음(첫인상) | 중(검색·지도 구조 손댐, 회귀 범위 큼) | 중상 | 다음 밤 |
| 찾기 | 중 | 낮음(DJFit 재사용) | 중 | 다음 밤 |
| 상세 | 매우 높음(가장 많이 열리는 화면, 공유 링크 착지점) | 낮음(순서 재배치 + 기존 부품) | 중 | 이번 밤 ① |
| 비교 | 높음(결정 지점) | 중(스와이프·표 격자 회귀) | 상 | 1안 무대 적용 뒤 |
| 임장 | 높음(차별화) | 높음(기록 손실 0 제약) | 상 | 이번 밤 ③ 연결만 |
| 나의 집감 | 중상(재방문 유도) | 낮음 | 낮음 | 이번 밤 ② |

선택: 상세 → 나의 집감 → 임장(연결). 이 셋이 "본다(상세) → 둔다(저장) → 다음에 한다(나의 집감) → 간다(임장)" 한 고리를 닫는다. 임장은 저장 구조를 건드리지 않는 범위로 묶는다.

### ① 상세: 가격·최근 실거래를 먼저, 층·일조·입지는 터치형

- 첫 화면(390): 상단 44 단지 이름 + 저장 하트. 그 아래 가격 카드 120px(최근 실거래 큰 글자 "6억 2,000", 날짜·층·면적 한 줄, 직전 거래 대비 화살표 없이 숫자만). 그 아래 최근 실거래 3건 리스트(각 56px). 그 아래 가로 칩 레일 3개 44px: "층별 가격" "일조" "입지" — 누르면 해당 블록으로 스크롤+펼침(일조는 1안 무대로 연결).
- 터치하면: 실거래 행 탭 → 같은 면적 거래만 필터된 리스트 시트. 하트 → 기존 저장 키에 추가, 토스트 "나의 집감에 담았어요 [보기]". 칩 → 블록 펼침, 다른 칩은 접힘.
- 코드 범위: templates 상세 블록 순서 재배치, 상세 전용 JS 100~150줄(칩 스크롤·펼침·필터 시트), style.css 상세 섹션 부분 수정 ≤80줄. 저장 키 변경 없음.
- 검증: 390/820/1440 가로 넘침 0, 첫 화면에 최근 실거래 금액 보임(y<300), 칩 3개 44px 이상, axe serious 0, 저장 후 나의 집감에 즉시 반영, 기존 공유 링크 앵커 유지.

### ② 나의 집감: 저장한 것·다음 할 일 먼저

- 첫 화면: 상단 "다음 할 일" 카드 1장(가장 가까운 임장 예정일 단지, "D-3 · 11월 11일 · 나릿재2 [길 안내]"). 없으면 "예정일이 없어요 [임장 계획 만들기]". 그 아래 저장한 단지 격자(2열, 카드 160px: 이름·최근 실거래·일조 결과가 저장돼 있으면 "약 5시간"). 그 아래 최근 본 단지 가로 레일.
- 터치하면: 할 일 카드 → 임장 화면 해당 단지. 저장 카드 → 상세. 길게 누르면 삭제 아닌 "빼기" 확인(기록은 남김). 카드 2개 이상 선택 → "비교" 버튼 등장.
- 코드 범위: 기존 저장 키 읽기만, 정렬·파생(D-day) 계산 JS 80줄, 템플릿 1개, CSS ≤60줄. 새 저장 키 0.
- 검증: 저장 0개/1개/10개 상태 각각 렌더, 저장소 비어도 오류 없음, 삭제 전 확인 시트, 축소 세로 640에서 할 일 카드와 첫 저장 카드가 모두 보임.

### ③ 임장: 후보·지도·예정일·현장 기록을 한 흐름으로 (연결만)

- 첫 화면: 상단 날짜 칩 레일(예정일 있는 날만), 그 아래 그날 코스 리스트(단지 순서, 각 행에 "기록 [연필]"), 지도는 접힘 "지도로 보기" 44px. 기록이 있는 단지는 행 오른쪽에 사진·메모 개수.
- 터치하면: 행 탭 → 현장 기록 시트(기존 기록 화면 그대로 안에 띄움), 저장 즉시 리스트에 개수 반영. 길 안내 → geo: 링크. 순서 바꾸기는 이번 밤 제외.
- 코드 범위: 기존 임장·기록 화면을 하나의 템플릿에서 시트로 호출하는 연결 JS 60~100줄, CSS ≤40줄. 저장 구조 변경 0, 이동(migration) 0. 기록 저장 경로는 기존 함수 호출만.
- 검증: 기록 10건 넣고 새 화면에서 읽기·수정·추가 뒤 저장소 원본 키 개수·내용이 1건도 안 바뀜(자동 테스트로 전후 JSON 비교). 시트 열린 채 뒤로가기 → 시트만 닫힘. 오프라인에서 기록 시도 시 기존 동작과 동일.

보류 이유 한 줄씩: 홈은 회귀 범위가 넓어 밤새 검증이 어렵고, 찾기는 효과 대비 급하지 않으며, 비교는 1안 무대가 확정된 뒤 같은 부품으로 만들어야 두 번 일하지 않는다.

## 요청 3. Android TWA 셸 — 더 할 것과 제약

우선순위 순.

1. 뒤로가기 정리: 시트·모달·필터는 열 때 history state를 넣고 popstate로 닫는다. 지금은 시트 위에서 뒤로가기를 누르면 화면 자체가 바뀌어 어르신이 길을 잃는다. 루트에서 뒤로가기는 앱 종료 그대로 둔다(가로채기 불가).
2. 당겨서 새로고침 차단: 지도·무대·리스트 스크롤 영역에 overscroll-behavior-y: contain. 레일·슬라이더 드래그 중 위로 당기면 페이지가 새로고침되는 사고 방지. 무대 SVG는 touch-action: pan-y 유지(세로 스크롤은 살림).
3. 안전 영역: viewport-fit=cover + 하단 탭에 env(safe-area-inset-bottom). 제스처 내비 기기에서 탭이 시스템 바와 겹치는 문제.
4. 오프라인·약한 통신: 서비스워커에 오프라인 대체 화면("통신이 안 돼요 · 저장한 단지는 볼 수 있어요") + 마지막으로 본 단지 5개 캐시. 지하·엘리베이터에서 임장 기록 화면이 흰 화면 되지 않게.
5. 작은 것 묶음: 버튼·칩에 user-select: none(길게 눌러 글자 선택되는 것 방지), 저장 성공 시 navigator.vibrate(10) 한 번, manifest shortcuts 3개(임장·비교·저장한 단지), 시스템 글자 크기 130%에서 레이아웃 검사(rem 기준인지).

제약(TWA로 불가 또는 조건부)
- 루트 화면의 뒤로가기 가로채기("한 번 더 누르면 종료") 불가.
- 상태바·내비바는 색만 바꿀 수 있고 완전 몰입(숨김)은 불가.
- 아이콘·앱 이름·시작 URL·색은 manifest를 바꿔도 스토어 재배포 전까지 반영 안 됨.
- 알림: 웹 푸시는 되지만 기본값은 "Chrome" 이름으로 뜬다. 앱 이름으로 띄우려면 android-browser-helper의 알림 위임 설정이 필요(네이티브 쪽 작업).
- 결제·구독은 Play Billing(Digital Goods API)만 가능, 일반 웹 결제 불가.
- 외부 앱 직접 실행은 geo:·tel:·intent: 링크 범위로만. 백그라운드 위치, 네이티브 파일 접근, 네이티브 바텀 탭·제스처 없음.
- 키보드 높이를 정확히 알 수 없어 입력창이 가려지는 경우는 scrollIntoView로만 대응.
