## 일조: 2.5D 유지 vs 가벼운 WebGL
| | 2.5D(현재 SVG) 개선 | WebGL(three.js) |
|---|---|---|
| 개발비 | 3~5일(추정) | 2~4주(추정) |
| 성능 | 구형 폰 가능 | 발열·끊김 위험 |
| 접근성 | 글자가 문서라 확대·읽기 가능 | 캔버스라 별도 글 요약 필요 |
| 거짓 표현 위험 | 낮음 | 창·발코니를 넣는 순간 가짜 외관 |
권고: **2.5D 유지.** 해 아이콘+해→창 점선(가리는 동에서 끊김), 문장형 라벨, 토글을 그림 밖으로. 이미 있는 평면·층별 보기가 각도 질문을 대신한다. WebGL은 "다른 각도" 요구가 실제로 확인될 때만, 자료에 있는 윤곽·높이·층수로 만든 무광 단색 블록만, "공공자료로 만든 모형, 실제 외관 아님" 문구 필수.
(이번 PR의 일조 개선은 층 강조·시점 전환·부드러운 시간 변화 중 **지금 가리는 동 강조만** 했다. 터치로 동 집중 시점 전환, 층 강조 개선은 하지 않았다.)

## 2) 구현 vs 시안, 가장 큰 차이 5개

1. **홈 진입 구조** — 시안: 아이콘+제목+한 줄 설명+›, 줄 전체가 버튼인 4줄. 구현: 질문형 문장 카드 3개, 아이콘·› 없음, 오른쪽에 글자 링크. 그리고 시안에 없는 통계·지도·홍보띠·접힌 섹션 5개가 아래로 6,000px 더 붙음.
2. **상세 머리·꼬리** — 시안: ‹ 뒤로, 공유, ♡ 헤더 / 이름 옆 등급 배지 / 화면 아래 고정 "임장 코스에 넣기". 구현: 홈과 같은 헤더(뒤로 없음), 작은 아이콘 5개 줄, 등급은 한참 아래 남색 카드에, 고정 CTA 없음.
3. **상세 가격 비교** — 시안: 두 가격 모두 84㎡ 기준이라 한 줄 메모면 끝. 구현: 99㎡ vs 84㎡로 기준이 달라 "면적 기준이 달라요…" 3줄 설명이 필요해짐.
4. **일조 장면 밀도** — 시안: 블록 3개(회색·주황 가리는 동·파랑 내 동)와 알약 라벨. 구현: 단지 전체 + 빗금 + 주황 4개 동 + 겹치는 라벨 + 왼쪽 세로 층 슬라이더(폭 20% 차지) + 그림 위에 얹힌 입체/평면/층별 토글.
5. **일조 헤더·동 칩** — 시안: 뒤로 화살표, 선택된 512동 칩이 파랗게 보임, 면책 문구는 카드 맨 아래. 구현: 칩이 501~505만 보여 선택한 512동이 안 보임, 면책 문구가 화면 첫 줄.

## 4) 일조 장면 평가와 권고

**설명 없이 이해되는가? — 아니오.** 이유 4가지(모두 캡처에서 확인):
- 주황 건물이 301·310·513 세 개(+잘린 506)라 "어느 동이 가리나"가 아니라 "주황이 뭐지"가 먼저 떠오름. 글로는 513동이 가장 크다고 했지만 그림에선 세 동이 같은 색.
- 해가 어디 있는지 표시가 없음. 빗금 띠가 그림자인지 바닥 무늬인지 알 수 없음.
- "301동 앞 동 · 23층" 라벨이 "301동 앞에 있는 동"인지 "301동이 앞 동"인지 읽기에 따라 다름.
- 빨간 ⊗는 "안 됨/오류"로 읽힘. "8층 창" 배지와 ⊗가 가까워 "8층 창이 막혔다"까지 추론해야 함.

**최소 수정(2.5D 유지, 3~5일 추정)**
1. 색 3개로 고정: 파랑=내 동, 주황=지금 시각에 가리는 동 1개, 나머지 회색 윤곽(채우기 없음).
2. 해 아이콘 + 내 동 창까지 점선 1개(해→창). 가리는 동이 선을 끊는 모양이면 설명 없이 이해됨.
3. 라벨은 "513동이 가려요 · 25층"처럼 문장형, 건물 바깥에 알약으로.
4. 빗금 삭제, 가리는 동 그림자만 연한 회색 다각형 하나(이미 계산된 고도·방위각으로 그릴 수 있음, 추정).
5. 층 슬라이더는 시안처럼 그림 아래 가로 − 8층 +, 토글·전체 보기는 그림 밖.

**2.5D vs 경량 WebGL(three.js)**

| | 2.5D (SVG/Canvas 2D) | three.js |
|---|---|---|
| 개발비 | 3~5일 (추정, 수정 중심) | 2~4주 (추정: 윤곽 압출, 그림자, 라벨, 터치, 폴백) |
| 용량 | 거의 0 | +150KB gz 내외 (추정) |
| 성능 | 구형 폰 OK | 구형 폰·저전력 모드에서 발열·끊김 위험, 배터리 |
| 접근성 | 글자·라벨이 DOM이라 확대·읽기 OK | 캔버스라 보조기기에 안 읽힘, 별도 텍스트 요약 필요 |
| 표현 | 한 시각·한 각도 정적 | 회전, 실제 그림자 투영, 층별 연속 |
| "사실처럼 그리기" 위험 | 낮음 | 높음 — 창·발코니·조경을 넣는 순간 가짜 외관이 됨 |

**권고: 2.5D 유지 + 위 5가지 수정.** 이미 "평면/층별" 보기가 있으므로 WebGL이 해결할 질문(각도 돌려보기)은 그 두 보기로 대신할 수 있음. WebGL은 사용자가 "다른 각도에서 보고 싶다"를 실제로 요구할 때만, 아래 조건으로:
- 건물은 자료에 있는 윤곽·높이·층수만으로 만든 **단색 무광 블록**, 창·발코니·지붕·나무·차 금지.
- 화면에 항상 "건물 윤곽·높이 공공자료로 만든 모형, 실제 외관 아님" 한 줄.
- 애니메이션 없음(해 시간 바꿀 때만 즉시 갱신), `prefers-reduced-motion` 무관하게 정적.
- 캔버스 옆에 같은 내용 글(지금처럼 "12:30 · 513동에 가려짐")을 반드시 유지.

## 5) 웹페이지 같은 부분 · 설명만 차지하는 공간 · 중복 카드

**웹페이지처럼 느껴지는 곳**
- 5개 화면 공통 "파란 소제목 → 두 줄 헤드라인 → 접힌 부제 ⌄" (홈·찾기·비교·프로젝트·나의 집감)
- 모든 화면 끝의 출처·약관·저작권 푸터
- 가로 탭 줄 마지막 탭이 잘림(찾기 "지도에서", 비교·프로젝트 "관심…")
- 홈 하단 "동네 온도 / 입주 예정 물량 / 구별 비교 / 입지 대비 가격이 낮은 단지" = 제목 + "펼쳐 보기" 버튼만 있는 접힌 섹션 4개 연속
- "전체 랭킹 보기→" 글자 화살표, 홍보 띠, 찾기의 긴 DSR/LTV 면책 문단

**설명만 차지하는 공간(줄이거나 ⓘ로 숨길 것)**
- 상세: "면적 기준이 달라요…"(3줄), 시세 섹션 머리말(2줄), 층별 시세 머리말(2줄), 단지 정보 머리말(3줄), 교통·학군 머리말(2줄), "종합 지수는 어떻게 계산됐을까요?" 카드 전체, 언덕·소음 체크의 연두색 안내 박스 2개
- 찾기: "조건을 고를수록 좁혀집니다", 점선 안내 박스, "결과" 빈 상태 문장, DSR 문단
- 일조: 첫 줄 면책, 표 아래 "같은 동·같은 층으로 계산한 값이에요…", "계산 근거·한계·자료 출처" 본문
- 나의 집감: "단지 화면의 '관심'을 누르면 여기에 모입니다…"(3줄)

**중복 카드**
- 나의 집감: 빈 상태 2개(같은 뜻, 버튼 2개)
- 비교: "0 / 2곳 이상" + "2곳 더 담으면 비교할 수 있어요"
- 찾기: 점선 안내 박스 ↔ "결과" 빈 상태 박스
- 상세: 상단 정보 카드 ↔ 남색 점수 카드(가격·세대·준공 중복) / "현장에서 확인할 점 1개" 바 ↔ "임장 때 직접 확인할 것" 카드 ↔ 상단 "현장 체크" 아이콘(세 군데) / "주요 특징" 타일(입지·학군) ↔ "교통·학군·생활 입지" 섹션
- 홈: 상단 "찾기·비교·임장 준비" 카드 3개 ↔ 하단 탭 "찾기·임장 준비" (같은 목적지, 추정) / 이웃 가격 비교 카드 4개마다 "나란히 비교" 버튼 반복
- 일조: "가장 크게 가리는 동 513동" ↔ "12:30 · 513동에 가려짐" ↔ 표 "가리는 동" 열
