# 일조 건물 시각화 2안 비교 실험 (A안 SVG 고급화 / B안 WebGL 3D)
기반: #324(장면 우선 구조) 위에서 `exp/sun-ab` 브랜치에 실험. **운영 화면은 바뀌지 않았고, 이 PR은 병합 대상이 아닌 실험 제출용 초안입니다.**
자료: `img/ab-4col.png`(지금 / 목표 시안 / A안 / B안), `img/ab-pairs.png`(같은 조건 A·B 쌍: 390 가림·일조, 다크, 360), `img/ab-demo.mp4`·`ab-demo.gif`(17초 조작: A안에서 층·시간·동 → 3D 켜기 → 층·시간·동·날짜 → 건물 직접 터치 → 원인 보기).

## 공통: 같은 데이터, 같은 계산
- 두 안 모두 `preview-calc.js`·`shadow.js`·`preview/*.json`을 **한 줄도 바꾸지 않고** 결과(`isoOpts`)만 받아 그립니다. 위치·높이·가림은 기존 계산 그대로.
- 3D에서 건물 역할(내 동 / 지금 가리는 동 / 하루 가리는 동 / 주변)을 계산 결과로 칠하고, 동 5 × 층 2 × 시각 6 × 날짜 2 = **120조합에서 "그림이 칠한 가림 상태 = 계산이 말한 가림 상태" 불일치 0**. SVG는 기존 90조합 불일치 0 유지.
- 실제 외관 자료가 없으므로 창문·벽 재질·조경·나무는 **그리지 않음**. 벽의 아주 옅은 가로 구분선은 층 수 표시일 뿐이며 화면 설명(접근성 문구)에 "실제 건물 외관이 아니다"를 적었습니다.

## A안: SVG 고급화 (`static/preview-iso.js`, `preview.css`)
벽 위→아래 그라데이션(밝음→어두움), 건물 밑 부드러운 접지 그림자 2겹, 흰 지붕 외곽선, 그림자를 줄무늬에서 부드러운 면으로, 선택 동 발광 그림자. 그리는 도형·판정 호출은 그대로.

## B안: WebGL 3D 시제품 (`scripts/gl/src/gl.js` → `static/preview-gl.js`)
three.js r187(MIT)로 건물을 윤곽 그대로 올려 세움. 해 방향 빛 + **실시간 그림자**, 하늘/땅 반구 조명, 건물 밑 접지 그림자, 선택 동 파랑 / 지금 가리는 동 주황 / 하루 가리는 동 연한 주황 / 주변 회색, **고른 층 노란 띠(빛 번짐 포함)**, 해 쪽 선과 가려지는 지점. 동·층·날짜·시각이 바뀌면 즉시 갱신, 동이 바뀌면 카메라가 260ms 부드럽게 이동(reduced-motion이면 즉시), 시각·층만 바뀔 땐 카메라 고정(화면이 흔들리지 않음). 건물을 직접 터치해 동 변경 확인(63번 시도 끝에 511동 선택, 날짜 유지). 기본은 꺼져 있고 `3D 보기` 버튼 또는 주소 `&e=gl`로만 켜짐.
- **WebGL 미지원/실패 시 SVG 유지**: `getContext` 차단 시험에서 3D 버튼이 숨고 SVG로 정상 표시, 오류 0.
- **느린 기기 보호**: 그리기 간격이 계속 길면 화질을 한 단계 낮추고, 그래도 느리면 안내를 띄우고 SVG로 되돌림(CPU 6배 감속 시험에서 확인).
- **화면 읽기**: 캔버스는 `aria-hidden`, 대신 현재 상태 전체를 읽어 주는 숨은 설명문 + 결과 카드(`aria-live`) + 동 버튼(레이블)은 SVG와 동일. reduced-motion에서 카메라 즉시 이동.

## 성능 비교 (로컬, **GPU 없는 소프트웨어 그리기(SwiftShader)** 환경 — 실기기 수치 아님)
| | SVG(A안) | WebGL(B안) |
|---|---|---|
| 코드 크기 | 14KB | **576KB (압축 147KB)** 추가, 3D를 켤 때만 내려받음 |
| 3D 준비까지(CPU 4배 느리게, 5회 중앙값) | 1.36초 | 1.80초 |
| 시간 24칸 조작 프레임 중앙값 (CPU 감속 없음) | 16.5ms | **75~79ms** |
| 같은 조작, CPU 4배 느리게 | 38.5ms | 100~133ms (24칸 중 14~23칸이 50ms 초과) |
| 긴 작업 합계(CPU 감속 없음/4배) | 0.7초/0.33초 | 1.4~1.5초/1.6~2.4초 |
| JS 메모리 | 3.9MB | 5.9MB (+ GPU 메모리는 측정 못 함) |
**해석 한계**: 이 PC에는 GPU가 없어 3D가 CPU로 그려집니다. 그래서 위 3D 수치는 실제 폰보다 훨씬 나쁘게 나옵니다. 하지만 반대로 "폰에서는 빠를 것"이라고도 말할 수 없습니다. 같은 환경에서 3D의 자동 보호(화질 낮춤 → SVG 복귀)가 실제로 작동한다는 것까지만 확인했습니다.

## 보급형 Android 검증 계획 (실행 전)
1. 갤럭시 A계열 등 RAM 3~4GB 기기 2종에서 SVG/3D 각각 같은 시나리오(동 3번·층 5번·시간 24칸·날짜 2번)로 Chrome 원격 점검(프레임 간격, 긴 작업, JS 힙)과 `adb shell dumpsys gfxinfo`(느린 프레임 비율), `dumpsys batterystats`(10분 사용 전후 배터리 %)를 기록.
2. 3D 첫 진입 시 576KB 내려받기 시간(LTE 느린 조건) 측정.
3. 합격선(제안): 3D에서 프레임 50ms 초과 비율 10% 미만, 첫 진입 3초 이내, 10분 사용 배터리 소모가 SVG 대비 2배 미만. 미달이면 3D는 기본으로 켜지 않음.
이 계획은 사용자 폰 2대 이상과 사용 승인이 필요해 아직 실행하지 않았습니다.

## 권고 (근거 있는 범위에서)
- **지금 단계의 기본값은 SVG 유지(A안).** 근거: ① 3D는 이 PC 환경에서 프레임이 4~5배 느리고 코드가 40배 큼 ② 실기기 검증이 없음 ③ 계산·접근성·대체 경로는 SVG가 이미 검증됨.
- 시각 품질 면에서는 **B안이 분명히 더 "건축 시각화"에 가깝습니다**(진짜 그림자·명암·깊이, 건물 윤곽 그대로). 다만 실제 외관 자료가 없어 시안의 사실적 질감까지는 못 갑니다.
- 따라서 제안: B안은 `3D 보기` 선택 기능으로 두고, **실기기에서 위 합격선을 통과하면 그때 기본값 승격을 결정**. 통과 못 하면 A안 고급화만 채택.
- 시안과의 남은 차이: 사실적 외관·나무·조경·밝은 하늘 질감, 상단 `일조/그림자/시간별` 탭, 하단 `일조 약 N시간` 막대, 층 드롭다운, 재생 버튼.
