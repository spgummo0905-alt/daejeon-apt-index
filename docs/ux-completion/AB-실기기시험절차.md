# 실기기 A/B(SVG vs 3D) 시험 절차 — 폰 2대 (저사양 1 + 평소 쓰는 일반 폰 1)
**현재 상태: 이 PC에는 adb가 설치돼 있지 않고 연결된 Android 기기도 없어서 실기기 시험은 NOT_TESTED입니다. 아래는 도구가 PC에서 끝까지 돌아가는지만 확인한 절차입니다.** (PC 점검 수치는 폰 성능이 아닙니다.)

## 준비 (한 번만)
1. PC에 Android 플랫폼 도구(adb) 설치 → 폰: 설정 > 휴대전화 정보 > 빌드 번호 7번 눌러 개발자 옵션 켜기 > **USB 디버깅** 켜기. USB로 연결하고 폰 화면의 "허용"을 누릅니다.
2. `adb devices` 에 기기가 `device` 로 보이는지 확인(폰 2대면 각각 `-s 기기번호`).
3. 폰에서 시험할 화면을 PC에서 서빙: 이 브랜치로 데모 사이트를 만든 뒤 `python3 -m http.server 8741 --directory <사이트폴더>`.
4. `adb reverse tcp:8741 tcp:8741` (폰의 localhost:8741 이 PC로 이어짐) 과 `adb forward tcp:9222 localabstract:chrome_devtools_remote`.
5. 폰 Chrome 을 열어 둡니다(다른 앱은 끔, 화면 자동 꺼짐 해제, 배터리 절약 모드 끔, 밝기 고정).

## 자동 측정 (SVG·3D 각각 5회 번갈아)
`cd scripts/device && npm install && node ab-device.mjs --url http://localhost:8741/preview.html --cdp http://127.0.0.1:9222 --label 저사양폰 --runs 5 --out 저사양폰.json` (일반 폰도 `--label 일반폰` 으로).
- 첫 진입 시간(실제로 한 번 그려진 시점), JS 메모리, 프레임 간격(시간 24칸 + 층 6칸): 중앙값·95·99백분위·최대, 33ms/50ms/100ms 초과 비율
- **진짜 터치 이벤트**로 버튼을 눌러 결과 글이 바뀔 때까지의 반응 시간
- 화면에 보이는 '다른 동' 건물 전부를 중심에서 눌러 선택 성공률(조작부에 가려진 건물은 `covered`로 따로 기록)
- 3D → SVG 전환 시 동·층·날짜·시각·결과 문구 보존, 글자 125%에서 가로 넘침·시간 바 가림
도구는 연결에 실패하면 값을 만들지 않고 끝납니다.

## 합격선 (강화안: 보급형에서 사용 중 30fps 우선)
3D를 **기본값 후보**로 올리려면 보급형 폰에서 모두 만족해야 합니다.
1. 프레임 간격 **중앙값 ≤ 33.4ms** 그리고 **95백분위 ≤ 50ms**, 50ms 초과 프레임 **5% 미만**, 100ms 넘는 끊김 **0~1회**
2. 터치 반응 중앙값 **≤ 100ms**, 최대 **≤ 300ms**
3. 첫 진입 **≤ 3초**(느린 4G 포함 ≤ 5초)
4. 화면에 보이는 동 터치 성공 **≥ 90%**(사람 직접 측정 기준)
5. 10분 배터리 소모가 SVG 대비 **2배 미만**, 발열 +3℃ 이내, 렌더러 PSS 증가 SVG 대비 +150MB 이내
6. 3D→SVG 전환 상태 보존, 글자 125%·TalkBack·두 손가락 모두 통과
**하나라도 못 넘으면 3D는 실험용으로 두고 SVG를 기본값으로 유지합니다.** 일반 폰만 통과하고 저사양이 실패하면 3D는 '고사양 자동 선택'이 아니라 끔 상태 유지가 기본입니다(자동 보호가 있어도).

## PC에서 한 도구 점검(성능 아님)
- 도구가 SVG·3D 각각 새로 불러오기 → 측정 → 건물 터치 → 3D→SVG 전환 → 글자 125% 검사를 끝까지 수행하고 JSON을 저장함을 확인.
- 3D→SVG 전환 상태 보존: 동·층·날짜·시각·결과 문구 모두 동일(`same: true`).
- 이 PC는 GPU가 없고 모바일 모양만 흉내 낸 것이라 프레임·반응 수치는 폰과 무관하므로 보고하지 않습니다.
