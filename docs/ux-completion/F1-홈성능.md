# WAVE F-1 홈 성능: 카카오 지도 지연 로딩
## 측정 (운영 사이트 `www.jipgam.kr/daejeon/?skip=1`, 390×844, 같은 조건 3회)
- Lighthouse 모바일: 성능 37 / 36 / 35, 접근성 100, 모범사례 100, SEO 100, CLS 0. FCP 3.5~4.0s, LCP 6.5~6.9s, **TBT 2.7~3.3s**(점수를 깎는 핵심). 로컬 데모의 50/70은 운영 수치가 아님.
- 원인 분리(CPU 4배 느림, 긴 작업 합계 중앙값): 기준 1,213ms / 지도 스크립트 막음 231ms / 단지 표 스크립트 막음 863ms / 둘 다 막음 70ms. 즉 ① 카카오 지도 SDK·묶음(clusterer) ② 전체 단지 표(1,064줄, 화면 요소 약 19,500개)가 원인.
## 변경
- `templates/index.html`: 지도 구역은 홈 아래쪽이라 첫 화면에 불필요 → 카카오 SDK + `kmap.js`를 **지도 구역 900px 전 또는 `#map` 주소로 들어올 때** 불러옴. 그 전까지는 기존 그림 지도(`map-fallback`)가 자리를 지킴. `kmap.js`/`cliffs.js` 코드는 수정하지 않음. IntersectionObserver가 없으면 즉시 로드(기존 동작).
## 효과 (운영 페이지에 같은 변경을 입혀 3회, 중앙값)
- 긴 작업 합계: **1,155ms → 277ms**. 첫 화면에서 지도 SDK 미로드(`typeof kakao === undefined`), 지도 구역으로 스크롤하면 실제 지도 표시(타일 10개, 컨트롤 표시, 오류 0), `#map` 주소 진입 시도 표시.
