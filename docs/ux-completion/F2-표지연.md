# WAVE F-2 홈 성능: 전체 단지 표를 필요할 때만 만들기
- 원인: 홈 아래 전체 단지 표(1,064줄)를 로드 뒤 한가할 때 미리 만들었는데, 줄을 끼우는 동안 화면이 약 0.9초 멈춤(긴 작업, 가장 긴 것 850~970ms).
- 변경(`static/table.js`): 로드 뒤 미리 만들기(`load → idle(build)`) 제거. 표 근처(600px 전)로 내려가거나, 구 필터·검색·`?area=`/`#list` 주소·`DJ.showArea`로 부를 때만 만듦. 첫 화면에는 HTML의 상위 30곳이 그대로 보임. 나눠 만들기(120줄씩)도 시험했으나 효과가 없어(1119→882ms 중 대부분 그대로) 채택하지 않음.
- 측정(운영 사이트에 변경을 입혀, CPU 4배 느림, 3회 중앙값): 표 변경만 차단 합 1,119→857ms. #322(지도 지연)와 함께 적용하면 첫 화면 긴 작업 합 1,078→13ms.
- 기능 확인: 첫 화면 줄 수 30, 표 구역으로 스크롤하면 1,064줄 생성, 검색 '둔산' 25개, `?area=서구#list` 151개 중 30개, 오류 0.
- 한계: Lighthouse 점수 변화는 배포 후 운영 3회 재측정 필요(NOT_DONE). 남은 원인: 스타일 계산 약 4.4초(화면 요소 약 19,000개), CSS 337KB(전송 68KB). 표로 늦게 내려가는 사용자는 줄 생성 시간(약 0.9초)을 그때 겪음. 노드 105 / 파이썬 298.
