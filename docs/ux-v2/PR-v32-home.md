# 지역 첫 화면(홈): 읽기 전에 시작 (ux/v32-home)
기준: main `3e2ee15`. UX v3.2 감사 H1~H4, H7과 추천 시안 1B+예산 칩.

## 문제 (운영 측정)
- 처음 온 사람의 첫 화면 주 버튼 "궁금한 아파트 찾기"는 같은 홈(`index.html`)으로 되돌아가 검색도 목록도 열리지 않음(시나리오 A 실패). 둘째 버튼 "한 화면에서 집 찾기"는 이름과 달리 임장 프로젝트 화면으로 감.
- 하단 메뉴 5개가 없어 갈 곳이 버튼 2개뿐. 통계 라벨이 "예시 지역"(운영 화면에서 숫자가 진짜인지 헷갈림). 버튼 높이 50px.

## 바꾼 것 (지역 첫 화면 `intro.html`, 맨 앞 지역 고르기 화면은 그대로)
- 큰 검색 칸(60px): 누르면 **기존 검색 창**이 열림(새 검색 기능 없음, `app.js`의 헤더 검색을 그대로 연결).
- 예산 칩 4개(3/5/7/10억 이하, 각 48px): 찾기의 기존 주소 조건(`finder.html?budget=N`)을 그대로 사용 → 누르면 "맞는 단지 N곳 보기"로 이어짐.
- 주 버튼 "조건으로 찾기"(찾기로 직접), 둘째 "지도로 보기"(지도로 직접), 각 56px·18px.
- 하단 메뉴 5개를 첫 화면에도 표시. 통계 라벨은 "대전 · 지수 산정 단지"처럼 실제 지역명.
- 작은 폰(높이 700 이하)에서는 설명 글·통계를 접어 핵심 요소가 하단 메뉴 위에 들어오게.

## 바꾸지 않은 것
- 지수·가격·자료, 찾기의 저장 키·계산, 지역 고르기 화면(맨 앞 주소), 아래쪽 소개 섹션, 카드 미리보기.
- 기존 시험 2곳의 문구 확인(옛 버튼 이름)은 새 구조로 맞췄음: 주 버튼이 `finder.html`로 가는지, 임장 입구(`projects.html`)가 하단 메뉴에 있는지로 확인하며 기준을 낮추지 않음.
