# PR 04b · 찾기 질문 4묶음 (ux/v2-finder-groups)
기준: PR 05(#341) 위. PR 04에서 "별도 승인 후"로 미뤘던 부분(질문 4묶음, 상황 질문 조건부)이며 사용자 승인("승인")을 받아 진행했습니다.

## 바꾼 것
- 화면 단계 표시가 8칸 → **4칸(예산 / 생활권 / 집 / 생활)**. 질문 자체는 그대로 7개를 묶음 순서로 이어서 묻습니다: 예산 → 지역·직장 → 평형·연식 → 역·학교·필수 조건. 질문 번호 줄은 `질문 3 / 7 · 생활권 2/2 · 하나만 고르세요`처럼 묶음과 단일/복수 선택을 함께 보여 줍니다.
- **주택 보유 상황**은 따로 묻지 않고, 예산에서 **'대출 한도 계산하기'를 고를 때만** 한 번 묻습니다(가격대로 고르면 안 나옴). 상황 칩을 누르면 예산 질문으로 이동.
- 하단 고정 줄의 "결과 보기 ›"를 "먼저 보기 ›"로(결과 수 줄은 필터 도중 언제든 접근 가능한 기존 동작 그대로).
- 단계 줄: 4칸이 폰 360~430에서 **한 줄에 다 보이고**(처음엔 360에서 가로로 밀어야 해서 작은 폭 규칙 추가), 단추 44px.

## 보존 (이주 없이 같은 후보 집합)
STEPS 8개의 **id와 순서, 저장된 설문의 step 번호**, `pass`·`fit`·`works`·`maxPrice`, 설문 저장 키, URL 조건(`?budget=&py=&must=`)은 그대로입니다. 옛 설문을 읽는 방식: step 0(상황)은 예산으로, 그 외 step은 같은 질문을 가리킴.
- 브라우저 확인: 옛 설문 `{budget:9, py:['30'], must:['big']}`를 step 0·2·3·4·5·6·7 각각으로 저장해 열었을 때 **결과 수 모두 18곳으로 동일**하고, 각 step이 같은 질문과 맞는 묶음에 놓임. 조건 없이 step만 0인 저장 설문은 전체 곳 수(48)와 같음. URL로 `?budget=9&py=30&must=big` 진입 시 마지막 묶음(생활)의 필수 조건으로 도착, 18곳.
- 질문 이동 순서: 예산 → 지역 → 직장 → 평형 → 연식 → 역·학교 → 필수 조건(7개), 마지막 버튼 "결과 보기".
