# PR 09 · 임장 준비와 현장 기록 (ux/v2-visit)
기준: main `e0f645b`. `project-store.js`·`visit-log.js`(데이터 의미)와 인증 구조는 바꾸지 않았습니다(시험으로 고정).

## 이미 있어서 그대로 둔 것
현장 모드는 이미 **저장에 실패하면 체크·호가·'다녀왔어요'를 되돌리고 실패 알림**을 띄웠고(`persist()`), 새 프로젝트 상자는 진행 중 프로젝트가 있으면 접혀 있었고, 위·아래 버튼(44px)·예정일·날짜 지남 안내·보관/다시 시작·닫기 전 확인(`confirm`)이 있었습니다. 저장이 확인되기 전에 '다녀옴'이나 도장을 보여주지도 않았습니다.

## 바꾼 것
- **프로젝트 맨 위 '다음 방문' 띠**: 다음에 갈 단지(번호·이름), 예정일 상태(남은 날/오늘/지남/없음), 다녀온 단지 N/전체, 현장 체크 시작 버튼, 방문 순서 칩(✓ 다녀옴 · 현재 표시). 값은 모두 이 프로젝트의 실제 방문 기록에서 계산. 모두 다녀왔으면 "기록으로 다시 비교하기".
- **방문 순서를 끌어서 바꾸기**: 후보 카드의 ≡ 손잡이를 잡고 위아래로(끌리는 카드가 뜨고 놓을 자리가 점선으로). 기존 ↑↓ 버튼은 그대로 있어 키보드로 같은 일을 할 수 있음. 저장은 후보 순서 하나뿐.
- **현장 모드 저장 상태 한 줄**(실제 결과만): 비회원 "이 기기에 저장돼요" / 회원 "이 기기에 저장됨 · 계정에 보내는 중…" / "이 기기와 내 계정에 저장됐어요." / 실패 "계정에는 보내지 못했어요. 이 기기에는 저장돼 있어요." + **다시 보내기**(체크·메모는 그대로). `sync.js`에는 상태 알림 이벤트와 재전송 함수만 추가.
- **다녀왔어요 → 도장 → 기록으로 다시 비교**: 저장이 확인된 뒤에만 "다녀옴 MM.DD" 도장(380ms, 줄이기 설정이면 즉시)과 "다녀온 기록으로 다시 비교하기" 버튼.
- **방문 기록 초안 보관**: 다른 단지로 갔다 돌아와도 쓰던 메모가 이 탭에 남고, 저장하면 지워짐(저장 구조 아님, 탭 임시 보관).

## 하지 않은 것
- 코스 좌표 미확인 단지를 위한 별도 화면, '다음 단지로 이동해도 현장 체크 항목 초안 유실' 외의 전용 점검은 하지 않음(체크는 누르는 즉시 저장되는 기존 구조).
- 시트 접근성 개편(PR 01 공통 시트로 교체)은 하지 않음.
- 회원 상태의 실제 계정 동기화 성공/실패는 데모에 계정 연결이 없어 **상태 이벤트를 흉내 내어** 화면 반응만 확인.
