# UX v4.8 · 찾기 조건을 지도·목록에서도 유지 (ux/v48-filter-share)
기준 main `8f51a9b`. 기획서 PR-1. 문제: 찾기에서 고른 조건이 지도·목록에 안 이어져 같은 조건인데 개수가 달랐음(찾기 38곳 vs 지도 51곳).

## 바꾼 것
- 새 `static/findcond.js`: 찾기의 조건 규칙(평형·연식·필수조건·거리·예산·지역)을 **글자까지 똑같이** 옮긴 읽기 전용 모듈. 시험이 finder.js 와 같은지 비교.
- 지도(점 지도·카카오 지도)·목록이 저장된 설문(`survey`)을 읽어 같은 조건으로 거름. **저장 형식·키·URL 불변, 쓰기 없음**(시험으로 보장).
- 지도 위 '찾기 조건' 칩(누르면 이 화면에서만 풀기, 44px 이상), '조건 바꾸기' 링크, '찾기 조건 다시 적용', 안내 문구.
- 0곳이면 가장 많이 늘어나는 조건 하나를 풀자고 제안(개수는 실제 계산), 하나만 풀어도 0곳이면 '모두 풀고 보기'.
- 찾기 결과에 '같은 조건으로 지도에서 보기' 링크(조건을 고른 뒤에만).

## 확인 (데모, 360/375/390/430 + 어두운 화면)
- 찾기 결과 ↔ 지도 핀 ↔ 목록: 4가지 조건(5억·30평 24곳, 7억·서구 11곳, 대단지·A등급 3곳, 0곳)에서 **단지 집합이 완전히 같음**. 지도↔목록 3회 왕복 후에도 같음.
- 칩을 눌러 풀어도 저장된 설문 값은 글자 그대로 불변. 넘침 0, 오류 0, 칩 높이 44px.
- Node 106 / Python 434 통과(새 시험 5개, 기존 지도 시험 1개는 기준 그대로 새 위치를 보게 고침).
