# UX v6.2 PR-A · 찾기 조건을 링크로 보내기 (ux/v62a-cond-link)
로드맵(JIPGAM_UX_v6_2) STEP 2 안 2. 승인: '추천대로'. **병합·배포는 별도 승인 전까지 하지 않음.**
## 해결하는 것
운영에서 직접 확인: 찾기 조건은 같은 기기의 지도에서는 유지되지만(저장된 설문), 지도 주소에 조건이 없어 링크를 받은 사람은 조건을 못 봄.
## 변경
- 찾기 결과에 '이 조건 링크 복사'. 주소 형식은 기존 찾기가 이미 읽는 `finder.html?budget=5&py=20#results` 그대로.
- '같은 조건으로 지도에서 보기'는 `map.html?budget=5&py=20`으로 이어짐. 직장 조건이 있으면 주소에 못 담으므로 지금처럼 저장된 조건으로 이어감.
- 지도는 주소에 조건이 있으면 그것을 우선 사용: 이름표 '링크 조건', 안내 '받은 링크의 조건이에요… 이 기기에 저장된 찾기 조건과는 별개예요'. 주소에 조건이 없으면 지금과 같음.
- 직장·내 위치는 개인 정보라 링크에 넣지 않음(복사 알림에도 안내).
## 지키는 것
저장 키·형식·survey 불변(링크 조건은 저장도 읽기도 안 함), 지수·등급·가격 계산 불변, 규칙은 finder.js와 같은 값 범위(없는 값은 버림).
## 확인(데모 사이트)
조건 고름 38곳 -> 링크 복사 -> 새 사람 브라우저: 찾기 38곳·같은 칩, 지도 '링크 조건' 칩 2개·38/51곳. 저장된 조건이 있는 사람이 다른 링크를 열면 링크 우선, 주소 없이 다시 열면 저장 조건 그대로. 조건을 풀어도 survey 저장 불변. 오류 0.
## 시험: Node 108 / Python 481 (+Node 2, +Python 4)
## 알려진 점
- 이상한 값(예: budget=999)은 찾기의 기존 주소 읽기와 같이 그대로 받아 '999억 이하'로 보이고 전체가 나옴. 값 범위 제한은 이번에 바꾸지 않음(찾기와 규칙을 같게 유지).
- 링크에 조건이 많으면 주소가 길어질 수 있음.
