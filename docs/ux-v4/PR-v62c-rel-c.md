# UX v6.2 REL-C · 두 기기 메모 충돌 시 양쪽 보존 + 연결 복구 시 자동 재전송 (ux/v62c-merge-notes)
승인: 시안 안 A + 자동 재전송 승인('ㅇㅇ 병합 배포'). 서버 표·SQL·저장 키·형식은 바꾸지 않음(앱 코드만).
## 조사로 확인한 문제 (임시 시험으로 재현)
1. 폰과 PC가 같은 단지 메모를 따로 고치면 나중에 고친 쪽만 남고 다른 쪽이 서버와 기기에서 사라짐(고친 시각만 비교해 덮어씀).
2. 인터넷이 끊겼다 돌아와도 자동으로 다시 보내지 않음('online' 이벤트 없음).
## 변경
- `static/sync.js` `mergeConflicts()`: 저장 전에, 이 기기에 아직 못 보낸 방문 기록(`visit:*`)만 서버의 같은 기록을 읽어, 서버 것이 이 기기가 마지막으로 본 것과 다르면 `R.mergeVisit`(처음 이을 때와 같은 규칙)으로 합쳐 새 수정으로 보냄. 합치면 '다른 기기에서 고친 메모와 합쳤어요' 안내.
  - 충돌이 아니면(서버가 마지막으로 본 그대로) 아무것도 합치지 않음 -> 평소에 지운 메모·체크·사진은 되살아나지 않음.
  - 확인 요청이 형식 문제(400·404·406·422)로 거절돼도 저장은 기존처럼 진행. 연결 문제·로그인 만료·계정 변경은 오류로 두어 기록을 지키고 '다시 시도'가 뜸.
- `static/sync.js`: `online` 이벤트에서 저장 상태가 오류일 때만 기존 '다시 보내기'를 한 번 부름(받아오기는 하지 않음).
- `static/field.js`: 합쳐진 메모가 열려 있는 메모칸에 바로 보임(옛 글로 다시 덮어쓰지 않게).
## 바꾸지 않은 것
`scripts/supabase_setup.sql`(서버 규칙 `where user_kv.t < excluded.t` 그대로), 저장 키·형식, 계정 분리, 사진 저장·삭제 규칙, `DJ.save`.
## 시험: Node 116 / Python 490 (새 Node 8, 새 Python 5)
두 기기 충돌 양쪽 보존·체크 합집합 / 충돌 아닌 수정·삭제는 그대로(되살아남 없음) / 방문 기록이 아닌 것·깨끗한 기록은 서버 확인 요청 없음 / 오프라인 보존 후 연결 복구 시 자동 재전송 / 대기 기록 없으면 아무것도 안 보냄·재전송 실패 시 오류 유지 / 다른 계정 기록 섞이지 않음 / 확인 요청 형식 거절 시 저장 계속 / 확인 중 연결 끊김 시 기록 보존·오류 표시. 합치기 코드를 끄면 해당 시험이 실패하는 것도 확인(시험이 실제로 잡음).
## 알려진 한계
- 두 기기가 동시에 고친 경우, 한쪽이 지운 내용이 합치기 때문에 되살아날 수 있음('잃는 것보다 중복이 낫다').
- 합쳐진 메모는 구분선 "— 함께 보관한 메모 —" 아래로 이어짐(길어질 수 있음).
## NOT_TESTED
