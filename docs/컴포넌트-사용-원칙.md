# 집감 화면 부품 사용 원칙 (감사 결과 + 규칙)

화면 부품 9쌍(토글·체크박스, 라디오·체크박스, 탭·세그먼트, 모달·바텀시트, 토스트·스낵바, 툴팁·팝오버, 칩·배지, 스피너·스켈레톤, 스테퍼·슬라이더)이 집감에서 목적에 맞게 쓰이는지 본 결과입니다.
측정은 데모 빌드를 휴대폰 폭(390)으로 열어 센 값입니다. 운영 화면 전체를 센 것이 아니며, **실제 사용자 시험·화면 읽기 도구 시험은 하지 않았습니다**(별도: `사용성-테스트-시나리오.md`).

## 1. 판정

| 쌍 | 집감 현황 | 판정 |
|---|---|---|
| 토글 / 체크박스 | 스위치(`role=switch`)는 옥상 설정 6개에만. 체크박스는 현장 체크리스트, 코스·후보 고르기, 조건 찾기(2룸 포함 등)에 | **유지** — 설정=스위치, 여러 항목 체크=체크박스로 이미 나뉨 |
| 라디오 / 체크박스 | 라디오(`role=radio`)는 옥상 16개. 조건 찾기는 버튼형 선택지(다시 누르면 해제) | **유지** |
| 탭 / 세그먼트 | 탭(`role=tab`) 홈·랭킹·옥상 20개, 세그먼트(`seg-btn`) 가격 기간·내 정보 등 14개 | **유지**. 세그먼트는 선택 상태가 화면 읽기 도구에 안 알려졌음 → **수정함(#266)** |
| 모달 / 바텀시트 | 모달(`aria-modal`)은 카드 만들기 등 4개, 현장 기록·알림 등은 바텀시트 | **유지**. 키보드가 올라온 크기(보이는 높이 45%)에서 현장 시트 입력칸이 모두 영역 안, 시트 안 스크롤, 가로 넘침 없음(360·390폭, 흉내 시험) |
| 토스트 / 스낵바 | 알림 영역이 모든 화면에 1개. 행동 링크가 붙은 알림 4곳 / 알림 호출 75곳. 실패 알림은 오래(읽을 시간) 표시 | **유지**. 알림 뒤판에 가려지는 문제는 #249 계열에서 수정 완료. '다시 시도' 버튼형 알림은 없고 문구로 안내 → 필요가 확인되면 후속 |
| 툴팁 / 팝오버 | 머리글의 지역·찾기·임장 팝오버(`rg-pop`, `tn-pop`) 6개. 마우스를 올려야 뜨는 툴팁은 없음 | **유지** — 휴대폰은 눌러서 여는 팝오버만 쓴다 |
| 칩 / 배지 | 칩 43개, 정보 배지 55개. 홈 칩은 한 번에 하나만 고르는데 선택 상태가 안 알려졌음(홈 22개 중 16개, 상세 19개 중 14개, 테마 6개 중 6개) | **수정함(#266)**. 배지가 눌리는 것처럼 보이는지는 시각 확인을 하지 않았음 |
| 스피너 / 스켈레톤 | 스켈레톤 0개, "불러오는 중…" 문구 3곳. 늦게 그려지는 조건 찾기 그림·질문은 자리를 미리 잡아 흔들림 0.30→0.05(#252) | **유지**. 스켈레톤은 **불필요**(자리 확보로 해결) |
| 스테퍼 / 슬라이더 | 스테퍼 0개. 슬라이더는 옥상 소리·빛번짐 5개뿐. 예산·금리·기간은 숫자 입력 + 가격대 칩 | **불필요** — 정확한 숫자에는 입력칸이 맞고, 슬라이더를 억지로 넣지 않는다 |

서울 25개 구 필터: 휴대폰에서 선택 상자 1개(높이 48px, 25개 구 + 단지 수, 탭 2번). 25개 칩 격자는 화면을 길게 차지해서 **현재 선택 상자 유지**. 강남구를 골랐을 때 표가 강남구 행만 남는 것을 운영 화면에서 확인(읽기만).

## 2. 사용 규칙 (앞으로 기능을 넣을 때)

**버튼 계층** — 한 화면에 가장 중요한 행동은 `btn primary` 하나. 보조는 `btn`, 드문 행동은 글자 링크. 높이는 44px 이상(어르신용 큰 버튼은 56px).

**고르는 것**
- 한 번에 하나 → 버튼형 칩/세그먼트(`active` 클래스). 화면 읽기 도구에는 `aria-pressed`가 자동으로 붙는다(`app.js` 끝의 한 곳). 같은 묶음 안에 `active`가 하나도 없는 묶음(행동 칩)은 표시하지 않는다.
- 여러 개 체크 → 체크박스(현장 체크리스트, 후보 고르기). 칩으로 여러 개를 고르게 하지 않는다.
- 켜고 끄는 설정 → 스위치(`role=switch` + `aria-checked`). 화면 이동·저장 같은 행동에는 쓰지 않는다.
- 정확한 숫자 → 숫자 입력칸(+ 자주 쓰는 값 칩). 범위를 훑는 경우에만 슬라이더.
- 화면 영역 이동 → 탭(`role=tab` + `aria-selected`). 같은 데이터를 다르게 보기 → 세그먼트.

**칩 vs 배지** — 칩은 눌러서 조건을 바꾼다(테두리·선택 색). 배지는 상태·정보만 보여 주며 눌리지 않는다(채워진 작은 글자 상자). 두 모양을 섞지 않는다.

**모달 vs 바텀시트** — 되돌릴 수 없는 확인·로그인은 모달(`aria-modal`, Esc로 닫힘). 휴대폰에서 이어서 하는 작업(현장 기록, 예산)은 바텀시트(높이 88vh 이내, 안쪽 스크롤).

**토스트** — 결과를 알릴 때만. 같은 제목이 떠 있으면 쌓지 않는다. 다음 행동이 있으면 링크를 붙인다. 실패는 이유를 읽을 시간만큼 길게. 알림은 바텀시트·뒤판보다 위(`z-index 100`).

**로딩·빈 화면·실패** — 로딩은 자리를 미리 잡아 화면이 흔들리지 않게(스켈레톤 대신 `min-height`/`aspect-ratio`). 빈 화면은 "아직 없음"과 다음에 할 일 한 줄. 실패는 원인(인터넷/저장 공간/로그인 연결 중)과 해 볼 일을 말로.

**글자·여백** — 제목·본문·보조 설명 3단. 숫자가 많은 표는 13~14px도 쓰지만, 안내 문장은 15px 이상. 휴대폰 360px에서 가로 넘침 0.

**움직임** — 이해·조작이 먼저, 장식은 `prefers-reduced-motion`을 지킨다.

## 3. CSS 현황 (정리 대상 메모, 이번에 바꾸지 않음)
- 최상위 규칙 3,115개 중 같은 선택자가 2번 이상 정의된 것 52개(`.brand`·`.pj-actions`·`.pj-candidate` 각 3회 등). 파일 끝에 보정 규칙을 덧붙이는 패턴이 계속되고 있음.
- 색 변수 76개 정의, `var()` 사용은 `--border` 200회·`--text` 180회 등. 그런데 직접 쓴 색상값(`#...`)도 774곳.
- 모서리 둥글기 값이 999·12·14·16·10·8·18·22px로 흩어져 있음. 글자 크기는 13px 241곳, 12px 183곳, 14px 157곳.
- 권장: 기능을 더할 때 같은 선택자가 이미 있으면 그 자리에서 고치고, 새 값은 기존 변수·값 중에서 고른다. 한꺼번에 갈아엎지 않는다(브랜드·카드 모양 유지).

## 4. 추가 점검 결과 (데모 빌드, 390폭)

- **홈 첫 화면**: 새 방문자는 "조건으로 찾기"와 "임장 준비 열기" 두 큰 버튼과 "단지 비교하기" 띠가 첫 화면에 보인다(360·390폭). 재방문자(관심 2곳)는 맨 위에 "이어서: 관심 단지 2곳 · 임장 코스 2곳" 칩이 생기고, 그만큼 "관심 2곳 비교" 띠가 아래로 밀려 하단 메뉴 바로 위에 걸친다(높이 780 기준 y=709, 하단 메뉴는 약 705부터). 작은 화면(높이 640 전후)에서는 접어야 보일 수 있음 → 사용자 시험에서 비교 행동을 찾는지 볼 것.
- **단지 상세 5개 범주**: 5개 링크 모두 눌렀을 때 해당 구역 제목 위치(약 156px, 고정 줄 아래)로 정확히 이동한다(움직임 줄이기 설정 켠 경우와 아닌 경우 모두). 다만 범주 줄은 화면 맨 위가 아니라 카드·"임장 때 직접 확인할 것"·주요 특징·지표 카드 아래(위에서 약 2,000px)에 있고, 따라다니는 바로가기 줄(시세·평형별·층별·단지 정보·입지·후기·거래)은 그 아래에서야 붙기 시작한다. 즉 "가격만 바로 보고 싶은" 사람은 두 화면쯤 내려야 한다. 순서를 바꾸는 것은 구조 변경이라 실제 사용자 시험 없이 바꾸지 않았다.
- **다크 모드 글자 대비**: axe 대비 규칙으로 10개 화면(홈·찾기·상세·비교·준비·카드·내 정보·랭킹·테마·역)을 밝은/어두운 화면 모두 검사해 위반 0. 단, axe는 그림·그라데이션 위의 글자는 판정하지 못해 "판정 불가"로 남기므로, 카드 위 점수 숫자 같은 곳은 눈으로 본 것에 그친다.

## 5. 아직 확인하지 않은 것
